# CDN 文件缓存

CDN 文件缓存是一个官方应用，用于在微擎面板中管理静态资源的缓存加速能力。它适合处理“如何让站点静态资源更快分发出去，并通过缓存规则降低源站压力”这类场景。

项目已开源：

- https://github.com/w7panel/w7panel-cdncache

## 这个应用能做什么

从当前前后端能力看，CDN 文件缓存主要覆盖下面几类事情：

- 为一个或多个域名开启文件缓存能力
- 配置源站地址和回源 Host
- 设置缓存规则和缓存时间
- 设置缓存键规则
- 查看域名列表和当前缓存配置
- 手动清空缓存
- 配合域名解析把缓存入口真正接通

如果你的目标是让站点中的图片、JS、CSS 等静态资源更快访问，同时希望在面板里集中维护缓存规则和源站配置，这个应用会更合适。

## 一、从哪里开始最合适

如果你是第一次使用 CDN 文件缓存，建议按下面顺序开始：

1. 先进入域名列表页
2. 新增一个需要开启缓存的域名
3. 根据提示完成 DNS 解析
4. 进入该域名的缓存配置页
5. 先配置源站信息，再配置缓存规则和缓存键规则
6. 验证缓存是否按预期工作

这个顺序更符合真实接入过程，也更容易判断问题出在解析、回源还是缓存规则本身。

### 添加域名之前先准备什么

在添加域名前，建议先确认：

- 你要加速的域名已经准备好
- 你知道它最终要回到哪个源站地址
- 你可以修改这个域名的 DNS 解析记录

如果这些准备没完成，后续即使把域名录进面板，也很难真正接通缓存链路。

## 二、域名列表页可以做什么

域名列表页是最基础的入口，当前至少支持：

- 查看已接入的域名
- 新增域名
- 删除域名
- 进入某个域名的缓存配置页
- 手动触发 **清空缓存**

### 新增域名

当前页面有独立的 **添加域名** 弹窗，用于录入需要接入缓存的域名。

已确认的可见能力包括：

- 添加多个域名
- 为每个域名单独设置是否自动 HTTPS
- 对域名格式做即时校验

如果域名格式不正确，页面会直接提示错误，因此建议在添加前先确认域名拼写和后续解析记录都准备好了。

## 三、DNS 解析提示怎么理解

当前前端里有专门的 **domain-parse-alert** 提示组件，说明这个应用不仅要求你在面板里录入域名，还会明确提醒你去 DNS 解析后台补充对应记录。

这意味着：

- 在面板里添加域名只是第一步
- 真正接通访问链路，还需要把域名解析到正确的缓存入口

如果域名已经添加成功，但访问没有经过缓存，通常要优先检查解析记录是否已经按提示配置正确。

## 四、缓存配置页可以做什么

进入某个域名后，会进入它的缓存配置页。当前页面至少包含下面三块核心配置：

- **节点缓存过期配置**
- **缓存键规则配置**
- **源站信息配置**

这三块分别回答的是：

- 哪些内容要缓存、缓存多久
- 哪些请求参数会影响缓存命中
- 缓存未命中时要回源到哪里

## 五、先调哪一类配置最合适

如果你是第一次配置一个域名，建议按这个顺序处理：

1. **先配源站信息**：先保证缓存未命中时，内容能正确回源
2. **再配缓存规则**：决定哪些资源缓存、缓存多久
3. **最后再调缓存键规则**：提升命中率，避免同类资源被拆成过多缓存对象

这样做更稳，因为如果源站本身就没配置对，先花很多时间调缓存规则通常也没有意义。

## 六、缓存规则怎么理解

缓存规则主要用来决定：

- 某类资源是否缓存
- 缓存时间是多少
- 缓存规则按什么范围生效

当前页面里支持按不同维度配置规则，例如目录、文件后缀名、文件全路径等。

如果你的目标是：

- 图片、JS、CSS 这类静态资源缓存更久
- 某些动态接口不走缓存
- 不同类型资源使用不同缓存时间

就通常要先在这里调整规则。

## 七、缓存键规则怎么理解

缓存键规则用于决定：

- 哪些请求参数会影响缓存内容
- 哪些请求其实可以命中同一份缓存

它的目的不是简单“多配一层规则”，而是帮助你提升缓存命中率。

如果同一个资源因为参数不同而被反复当成不同对象缓存，就应该回头检查缓存键规则是否配置合理。

## 八、源站信息配置

源站信息配置决定了缓存未命中时，请求会回到哪里取内容。

当前页面里已经明确支持：

- **源站地址**
- **源站 HOST**

如果缓存已经接入，但内容始终不对、回源失败或资源返回异常，通常就要优先检查这部分配置。

## 九、清空缓存什么时候会用到

列表页里提供了 **清空缓存** 操作。

这个能力适合以下场景：

- 静态资源已经更新，但访问仍然是旧内容
- 规则已修改，需要让旧缓存失效
- 某个域名的缓存状态需要立即刷新

在使用清空缓存前，最好先确认两件事：

1. 源站内容已经是正确版本
2. 问题确实出在旧缓存，而不是解析或回源本身

如果这两点没有先确认，清空缓存往往只是重复操作，不能真正解决问题。

## 十、常见使用链路

如果你是第一次使用 CDN 文件缓存，通常可以按下面顺序操作：

1. 新增需要加速的域名
2. 按提示完成 DNS 解析
3. 配置源站地址和源站 HOST
4. 设置缓存规则和缓存键规则
5. 验证资源访问是否按预期命中缓存
6. 如果资源更新后仍旧返回旧内容，再按需要清空缓存

这条链路更适合实际接入和后续维护，而不是只停留在“把域名加进去”。

## 十一、什么时候优先检查这个应用本身

如果你遇到下面这些情况，通常要先回到 CDN 文件缓存应用里排查：

- 域名已经添加，但访问没有走缓存
- 缓存规则已经配置，但命中率不符合预期
- 请求能到源站，但内容返回异常
- 资源已经更新，但访问仍然是旧内容
- 回源 Host 或源站地址配置不正确

## 使用建议

- 先把域名解析链路接通，再细调缓存规则
- 缓存规则和缓存键规则不要同时随意改，尽量一次只改一块，方便判断效果
- 如果内容异常，先区分是“解析问题”“回源问题”还是“缓存规则问题”
- 清空缓存前，先确认源站内容已经是正确版本

CDN 文件缓存的价值，在于把“域名接入、缓存规则、回源配置和缓存清理”这些原本分散的工作，整理成一套可在面板里持续维护的文件缓存能力。
