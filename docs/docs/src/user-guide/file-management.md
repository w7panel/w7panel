# 文件管理

文件管理用于直接操作应用运行环境中的文件。这里处理的通常不是你本地电脑里的文件，而是容器或应用内部的目录、配置文件、压缩包、静态资源和运行产物。

在当前面板里，文件管理相关的常见能力包括：

- **文件管理**
- **文本编辑器**
- **WebDAV 文件访问**
- **压缩 / 解压**
- **权限修改**
- **挂载文件编辑**
- **分片上传**

## 进入文件管理

通常可以按下面的方式进入：

1. 进入 **应用管理**。
2. 找到目标应用。
3. 点击 **文件管理**。

进入后，你会看到当前应用目录、文件列表、路径导航和常见操作按钮。

除了应用详情里的 **文件管理**，当前面板还存在节点侧的隐藏文件管理页，主要用于节点级排查和查看。但对大多数用户来说，日常最常用的还是应用详情里的文件管理入口。

如果你要修改应用运行中的配置、上传资源、下载目录或排查文件问题，通常都会从这里开始。

## 文件管理里最常用的操作

文件管理最常见的高频操作包括：

- 上传文件
- 新建文件或目录
- 下载文件或目录
- 删除文件或目录
- 重命名
- 压缩和解压
- 修改权限
- 打开 **文本编辑器**

这些操作多数都直接影响应用运行环境，所以建议在执行前先确认目标路径和文件用途。

## 上传文件

### 常见操作步骤

1. 点击 **上传文件**。
2. 选择本地文件。
3. 等待上传完成。

如果页面支持拖拽上传，也可以直接把文件拖进文件区域。

### 适合的场景

- 上传静态资源
- 上传配置文件
- 上传脚本或备份包
- 上传较大的安装文件或资源包

如果文件较大，页面可能会通过分片方式完成上传。这类场景下，建议等待上传完全结束后再进行后续操作。

## 新建文件或目录

1. 点击 **新建**。
2. 选择新建文件或新建目录。
3. 输入名称。
4. 确认创建。

这个能力通常适合快速补充配置、目录结构或临时文件。

## 下载文件或目录

### 下载单个文件

- 直接点击下载或复制类按钮进行下载。

### 下载目录

- 目录通常会先被打包，再提供下载。

如果你要导出整批内容，通常先压缩再下载会更方便。

## 删除和重命名

### 删除文件或目录

1. 勾选目标文件或目录。
2. 点击 **删除**。
3. 确认删除。

> 删除操作通常不可恢复，执行前建议再次确认路径和内容。

### 重命名

1. 选中文件或目录。
2. 进入重命名操作。
3. 输入新名称并确认。

如果某些配置文件被应用明确引用，重命名后可能会直接影响应用运行。

## 压缩与解压

### 压缩文件或目录

1. 勾选要压缩的文件或目录。
2. 点击 **压缩**。
3. 选择压缩格式和保存位置。
4. 确认执行。

### 解压文件

1. 找到压缩文件。
2. 点击解压操作。
3. 选择解压目标路径。
4. 确认执行。

这类能力通常适合备份目录、导入资源包、处理安装文件或批量整理内容。

## 修改权限

文件权限问题在容器场景里非常常见。

### 什么时候需要改权限

- 文件存在，但应用读不到
- 脚本存在，但执行不了
- 目录存在，但程序写不进去

### 操作步骤

1. 勾选目标文件或目录。
2. 点击 **权限**。
3. 设置权限或所有者。
4. 根据需要决定是否递归应用到子目录。
5. 确认保存。

如果你修改的是运行中的应用配置目录，权限变化后建议同时观察应用状态和日志。

需要注意的是，某些特殊文件类型并不支持权限修改；如果目标文件来自挂载配置，也可能无法直接在这里修改权限。

## 文本编辑器

如果你需要快速修改文本文件、配置文件或脚本，可以直接打开页面里的 **文本编辑器**。

### 适合的场景

- 临时修改配置
- 查看和调整脚本
- 快速修正文本内容
- 在文件树里连续查看多个文件

### 不太适合的场景

- 大规模开发
- 长时间编码
- 复杂重构

文本编辑器更适合“快速维护”，不建议完全替代正式开发环境。

### 在线编辑时要注意什么

- 当前文件过大时，不适合直接在线编辑
- 某些二进制文件或特殊文件类型不适合在文本编辑器里打开
- 修改后如果应用仍在运行，最好结合日志和实际行为确认变更是否生效

当前界面里对大文件有明确限制：如果单个文件超过 1MB，通常不支持直接在线编辑，更适合下载后修改，再重新上传。

## WebDAV 文件访问怎么理解

文件管理底层使用的是 WebDAV 文件访问能力，所以很多文件读写、目录浏览、移动、复制等操作，本质上都是通过一套标准化文件访问链路完成的。

对普通用户来说，不需要记住 WebDAV 细节，但可以这样理解：

- 面板里的文件管理不是“本地模拟文件树”
- 它操作的就是目标应用运行环境里的真实文件
- 这也是为什么文件操作、权限和路径会直接影响应用运行结果

这也意味着，文件列表、目录浏览、重命名、复制、移动等很多操作，实际上都直接作用在目标环境里，而不是先写到某个临时区域再同步。

## 挂载文件什么时候会用到

有些文件不是普通目录里的静态文件，而是通过挂载方式提供给应用使用的配置内容。

这类场景常见于：

- 应用配置来自 ConfigMap 或 Secret
- 某些文件在容器内看得到，但来源其实是挂载对象
- 你需要改的是“挂载出来的配置”，而不是普通目录里的独立文件

如果你改完文件却发现应用行为没有按预期变化，就需要确认你改的是普通文件，还是挂载文件。

## 文件管理里常见问题怎么判断

如果你在文件管理里遇到问题，建议先从这几个方向判断：

1. 文件路径是否正确
2. 文件权限是否允许当前操作
3. 上传、下载或解压是否成功完成
4. 修改后应用是否需要重新加载或重启
5. 目标文件是否属于挂载文件或特殊来源
6. 文件是否过大，或并不适合在线编辑

很多时候，问题不是“文件没改成功”，而是“改完以后应用还没按新的状态运行”，或者“改的不是实际生效的那份文件”。

## 使用文件管理时的建议

- 删除、覆盖和权限修改都属于高影响操作
- 修改配置前最好先确认目标文件作用
- 批量操作前先核对选中的文件或目录
- 修改运行中应用的文件后，记得同时关注日志和运行状态
- 遇到异常时，不只看文件列表，还要结合应用状态一起判断

文件管理的价值，不只是让你“看到文件”，而是让你能在应用运行环境里快速完成那些本来必须靠命令行处理的高频维护动作。
