# 反向代理

反向代理用于把外部请求转发到目标服务。它更适合处理“已有服务怎么被访问”这类问题，而不是“如何创建一个新应用”。

在当前面板里，反向代理不仅有独立的 **反向代理** 列表页，还有对应的 **域名管理** 子页，用来继续处理反向代理自身的访问入口配置。

## 进入反向代理

1. 登录微擎面板。
2. 在左侧菜单进入 **应用管理**。
3. 点击 **反向代理**。

如果你已经创建了反向代理对象，后续通常还会继续进入它对应的 **域名管理** 子页，处理域名和访问入口问题。

## 适合什么场景

常见场景包括：

- 把外部请求转发到内部服务
- 为已有服务补充统一访问入口
- 让某个路径指向指定目标地址
- 按路径拆分不同后端服务

如果你的目标不是“部署一个新应用”，而是“让已有服务按某种方式被访问”，通常反向代理会更合适。

## 新建反向代理

1. 进入 **反向代理** 页面。
2. 点击 **新建**。
3. 填写域名或入口信息。
4. 设置目标地址。
5. 根据需要配置路径规则。
6. 确认保存。

创建完成后，建议立刻验证访问结果，确认请求是否已经被正确转发到目标服务。

## 路径规则什么时候重要

如果一个域名下不只承载一个简单页面，而是：

- 主站和 API 分开
- 不同路径对应不同服务
- 静态资源和动态请求分开

这时路径规则就非常关键。

如果页面能打开，但资源加载错乱、接口请求异常或某些路径返回不对，通常要优先检查路径规则。

## 编辑或删除反向代理

在反向代理列表中，通常可以继续做这些操作：

- 编辑现有代理配置
- 修改目标地址
- 调整路径规则
- 进入对应的 **域名管理** 子页
- 删除不再使用的代理

如果当前代理已经在线上对外使用，修改前最好先确认影响范围，避免直接影响正在访问的业务。

## 访问异常时怎么判断

如果通过反向代理访问异常，建议先按这个顺序判断：

1. 目标服务本身是否正常运行
2. 域名或入口是否已经接通
3. 路径规则是否配置正确
4. 请求是否被转发到了正确目标

很多“反向代理有问题”的情况，最后并不是代理本身坏了，而是目标服务、路径配置或访问入口没有对齐。

## 使用反向代理时的建议

- 先确认目标服务本身可用，再配置代理
- 一个域名对应多个服务时，要优先规划路径规则
- 修改线上代理前，先确认会影响哪些现有访问路径
- 遇到问题时，不只看入口本身，也要看目标服务是否真的正常返回

反向代理的价值，在于把已有服务更稳定地接到访问链路上。
