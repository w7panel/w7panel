# 存储管理

存储管理用于处理应用的持久化数据和底层存储资源。很多业务应用真正重要的不只是“程序在不在运行”，而是“数据有没有保留下来、卷有没有正常挂载、空间够不够用”。

在当前面板里，存储管理相关的常见页面包括：

- **存储设备**
- **存储分区**
- **快照管理**

在实际使用中，你还会经常遇到和卷状态、Longhorn 卷、扩容、挂载状态相关的检查和维护工作。

## 进入存储管理

1. 登录微擎面板。
2. 在左侧菜单进入 **存储管理**。
3. 根据需要进入 **存储设备**、**存储分区** 或 **快照管理**。

如果你遇到数据写入失败、卷一直 Pending、容量不足、快照恢复或卷状态异常等问题，通常就要优先回到这里处理。

需要注意的是，当前面板的默认进入页就是 **存储设备**。如果你是第一次进入存储管理，通常最先看到的会是设备层的信息，而不是分区列表。

## 存储设备

**存储设备** 更适合看底层存储资源本身。

### 进入后通常先看什么

- 哪些节点有可用存储
- 总空间和可用空间是否正常
- 某个节点是否明显接近容量上限
- 存储设备是否存在异常状态

### 什么时候优先看存储设备

如果你遇到下面这些情况，建议先看 **存储设备**：

- 应用卷本身没报错，但实际空间明显不够
- 某个节点的存储使用率异常偏高
- 怀疑问题出在节点底层存储，而不只是单个 PVC

如果卷表面正常，但实际容量或性能不对，通常就要继续看存储设备。

如果当前环境还没有安装 Longhorn，设备页通常也会直接提示对应组件未安装，并提供进一步处理入口。

## 存储分区

**存储分区** 更偏向应用实际会使用到的持久化存储。

### 进入后通常先看什么

- 分区或卷名称
- 存储类型
- 容量和已用空间
- 访问模式
- 当前状态

### 创建存储分区

通常可以按下面顺序处理：

1. 进入 **存储分区** 页面。
2. 点击 **新建**。
3. 填写名称、容量、访问模式和相关配置。
4. 确认创建。
5. 在应用配置中使用对应存储。

如果应用依赖数据库目录、上传目录、缓存目录或业务文件目录，建议在应用创建前就先把存储规划好。

在当前界面里，存储分区不仅仅是“一个卷列表”，还会继续关联卷大小、快照大小、副本数和扩容状态等信息，所以很多后续维护工作也会从这里继续进入。

### 什么时候优先看存储分区或卷状态

如果你遇到下面这些问题，建议先看 **存储分区** 或相关卷状态：

- 应用启动后无法写入数据
- 数据目录没有按预期保留
- 卷长时间处于 Pending
- 应用迁移后数据没有跟上
- 某个 PVC 已创建，但实际没有成功挂载

这类问题很多表面看起来像应用问题，实际上往往是卷状态或挂载状态异常。

## Longhorn 和卷状态怎么理解

如果你的环境使用了 Longhorn，面板里会更强调卷状态、快照、扩容、挂载和卷维护这些操作。

从使用角度看，可以先这样理解：

- **卷状态**：判断卷当前是不是健康、是不是已经挂载成功
- **挂载 / 卸载**：确认卷当前挂在哪个节点或应用上
- **扩容**：当容量不够时继续扩大卷空间
- **快照**：在关键时间点保留卷状态，便于恢复或回滚
- **卷维护**：处理一些更偏存储层的操作，例如清理、恢复或状态修复

如果你在应用层看不到明显错误，但数据卷状态异常，通常要优先回到这些信息继续判断。

### 当前面板里和 Longhorn 更贴近的常见操作

结合现有实现，Longhorn 相关能力不只是“看一眼状态”，通常还会涉及：

- 查看卷状态和副本信息
- 判断卷是否处于扩容中
- 判断卷是否被占用或锁定
- 查看快照数量和快照总大小
- 进入快照管理继续删除或清理快照

这意味着如果你已经确认应用本身没有明显问题，但卷状态、快照或挂载行为异常，就应该把重点放到 Longhorn 相关信息上。

## 快照管理

**快照管理** 适合处理“保留某个时间点的数据状态”这类工作。

在当前面板里，**快照管理** 不是一个长期常驻的一级列表入口，而更像是从 **存储分区** 或卷相关信息继续进入的隐藏页面。

### 什么时候会用到快照管理

- 做重要变更前，先保留当前状态
- 需要回滚保护时
- 需要恢复到某个已知时间点时

### 进入快照管理前先确认什么

- 当前卷是否健康
- 目标快照对应的是哪一份数据
- 恢复操作会不会影响正在运行的业务

快照不是普通备份文件，而是更贴近卷状态本身的保护手段，所以在恢复前要先确认影响范围。

当前实现里，快照相关操作不只包括查看，还可能继续做：

- 删除快照
- 清理快照

所以在执行这些动作前，建议先确认当前卷和应用是否还在使用这部分数据。

## 备份、扩容和快照怎么区分

这三件事都和数据安全有关，但用途不同：

- **备份**：防止数据丢失
- **扩容**：解决空间不够的问题
- **快照**：保留某个时间点的状态，便于恢复或回滚

### 什么时候需要备份

- 应用要做大版本调整前
- 要迁移数据前
- 关键业务数据需要长期保留时

### 什么时候需要扩容

- 容量已经接近上限
- 应用写入越来越多
- 卷状态正常，但空间明显不够

### 什么时候考虑快照

- 做重要变更前
- 准备回滚保护时
- 需要保留某个时间点的数据状态时

## 什么时候说明问题在存储层

如果你看到下面这些现象，通常要优先怀疑存储层：

- 应用写入失败
- 卷无法正常绑定或挂载
- 容量不足导致服务异常
- 数据丢失或目录内容异常
- 应用迁移后数据状态不一致
- Longhorn 卷状态不健康
- 快照数量异常或快照清理后空间没有按预期释放

这时继续只看应用日志通常不够，还需要回到 **存储分区**、卷状态、**快照管理** 和容量使用情况一起判断。

## 使用存储管理时的建议

- 在正式应用上线前，尽早明确数据目录和持久化方式
- 对重要数据提前考虑备份策略
- 容量接近上限时尽早处理，不要等到应用报错再扩容
- 做迁移、恢复或删除前，先确认数据影响范围
- 出现问题时，不只看应用状态，也要同时看卷状态和底层存储状态

存储管理的价值，不只是让应用“有地方写数据”，而是让数据在应用长期运行过程中保持可用、可控、可维护。
