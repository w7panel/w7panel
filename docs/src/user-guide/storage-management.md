# 存储管理

存储管理用于处理应用的持久化数据和底层存储资源。很多业务应用真正重要的不只是“程序在不在运行”，而是“数据有没有保留下来、卷有没有正常挂载、空间够不够用”。

在当前面板里，存储管理相关的常见页面包括：

- **存储设备**
- **存储分区**
- **快照管理**

在实际使用中，你还会经常遇到和卷状态、Longhorn 卷、扩容、挂载状态相关的检查和维护工作。

## 进入存储管理

1. 登录微擎面板。
2. 在左侧菜单进入 **存储管理**。
3. 根据需要进入 **存储设备** 或 **存储分区**；快照从分区的相关信息进入。

如果你遇到数据写入失败、卷一直 Pending、容量不足、快照恢复或卷状态异常等问题，通常就要优先回到这里处理。

需要注意的是，当前面板的默认进入页就是 **存储设备**。如果你是第一次进入存储管理，通常最先看到的会是设备层的信息，而不是分区列表。

## 存储设备

**存储设备** 更适合看底层存储资源本身。

### 进入后通常先看什么

- 哪些节点有可用存储
- 总空间和可用空间是否正常
- 某个节点是否明显接近容量上限
- 存储设备是否存在异常状态

### 什么时候优先看存储设备

如果你遇到下面这些情况，建议先看 **存储设备**：

- 应用卷本身没报错，但实际空间明显不够
- 某个节点的存储使用率异常偏高
- 怀疑问题出在节点底层存储，而不只是单份应用存储

如果卷表面正常，但实际容量或性能不对，通常就要继续看存储设备。

如果当前环境还没有安装 Longhorn，设备页通常也会直接提示对应组件未安装，并提供进一步处理入口。

## 存储分区

**存储分区** 更偏向应用实际会使用到的持久化存储。

### 进入后通常先看什么

- 分区或卷名称
- 存储类型
- 容量和已用空间
- 访问模式
- 当前状态

### 创建存储分区

创建前先规划数据库、上传文件等目录的容量和保存方式，填写步骤与访问模式见本节下方的“创建分区与访问模式”。创建后还需要在应用配置中选择并连接这份存储。

### 什么时候优先看存储分区或卷状态

如果你遇到下面这些问题，建议先看 **存储分区** 或相关卷状态：

- 应用启动后无法写入数据
- 数据目录没有按预期保留
- 卷长时间处于 Pending
- 应用迁移后数据没有跟上
- 数据空间已创建，但实际没有连接到应用

这类问题很多表面看起来像应用问题，实际上往往是卷状态或挂载状态异常。

### 创建分区与访问模式

1. 进入 **存储分区**，点击新建。
2. 填写名称和需要的容量。
3. 根据应用要求选择存储类型和访问模式。
4. 保存并等待状态就绪。
5. 在应用配置中，将需要长期保存的目录连接到这份存储。

创建时还可以选择存储设备，或使用已经准备好的网络共享目录（页面称为 nfs），后者需要填写共享服务器地址和目录。

| 页面选项 | 含义 |
| --- | --- |
| ReadWriteOnce | 限制在一台服务器上读写，不代表只允许一个程序使用 |
| ReadWriteMany | 支持多台服务器读写，但应用本身也必须支持共享数据 |

列表分“手动创建”和“自动创建”：手动分区可在安装应用时选择；自动分区由应用管理，不供多个应用混用。

创建分区后，还要确认应用实际使用了它。可以在应用的指定目录中写入测试文件，再按应用维护要求验证数据是否保留。

### 使用示例：保存上传文件

假设应用说明要求将上传文件保存在 `/app/uploads`，预计需要 10 GiB：

1. 手动创建分区，名称例如 `website-uploads`，容量选择 10 GiB，并选择当前集群可用的存储类型。
2. 等待就绪，在应用的存储配置中选择这份分区，连接到 `/app/uploads`。
3. 保存应用配置，等待运行正常后，通过应用上传一份测试文件。
4. 在该目录确认文件存在，再按应用维护要求重启并检查测试文件仍可读取。

目录必须以自己的应用说明为准；把存储连接到另一个目录不会自动保护真正的上传文件。连接后原目录中的文件可能暂时看不到，已有文件应先备份并安排迁移，不要直接覆盖正在使用的业务目录。

## Longhorn 和卷状态怎么理解

如果你的环境使用了 Longhorn，面板里会更强调卷状态、快照、扩容、挂载和卷维护这些操作。

从使用角度看，可以先这样理解：

- **卷状态**：判断卷当前是不是健康、是不是已经挂载成功
- **挂载 / 卸载**：确认卷当前挂在哪个节点或应用上
- **扩容**：当容量不够时继续扩大卷空间
- **快照**：记录某个时间点的数据状态；本页没有创建和恢复入口
- **卷维护**：查看存储状态、清理不再需要的快照等；恢复和状态修复需要管理员另行处理

如果你在应用层看不到明显错误，但数据卷状态异常，通常要优先回到这些信息继续判断。

### 当前面板里和 Longhorn 更贴近的常见操作

结合现有实现，Longhorn 相关能力不只是“看一眼状态”，通常还会涉及：

- 查看卷状态和副本信息
- 判断卷是否处于扩容中
- 判断卷是否被占用或锁定
- 查看快照数量和快照总大小
- 进入快照管理继续删除或清理快照

这意味着如果你已经确认应用本身没有明显问题，但卷状态、快照或挂载行为异常，就应该把重点放到 Longhorn 相关信息上。

## 快照管理

快照记录某个时间点的数据状态，可以辅助恢复。快照仍可能依赖当前存储设备，不能代替保存在其他位置的独立备份。

在分区列表点击 **快照总大小** 中的数值进入快照管理。核对所属分区、时间和大小：

1. 不再需要的快照可以点击 **删除**。
2. 标记为 **待删除** 后，可以点击 **清理**，等待释放空间。
3. 清理会处理这份分区上已标记删除的快照，不限于当前点击的那一行。

当前页面用于查看、删除和清理快照，没有创建或恢复入口。需要恢复数据时，请管理员使用经过确认的备份或存储维护方案。

## 备份、扩容和快照怎么区分

这三件事都和数据安全有关，但用途不同：

- **备份**：防止数据丢失
- **扩容**：解决空间不够的问题
- **快照**：保留某个时间点的状态，便于恢复或回滚

### 什么时候需要备份

- 应用要做大版本调整前
- 要迁移数据前
- 关键业务数据需要长期保留时

### 什么时候需要扩容

- 容量已经接近上限
- 应用写入越来越多
- 卷状态正常，但空间明显不够

### 什么时候考虑快照

- 做重要变更前
- 准备回滚保护时
- 需要保留某个时间点的数据状态时

### 实际扩容时的注意事项

查看分区容量和服务器可用空间。页面提供扩容操作时，按提示增加容量，并等待处理完成。扩容过程中可能需要暂时断开数据空间、重新连接并重启应用。选择业务低峰期操作，等待页面显示完成后再检查容量和写入。是否支持扩容与当前存储类型有关。

页面中的“卷”也是数据空间的名称；“挂载”表示把它连接到应用，“卸载”表示断开连接。正在被应用使用的空间不要随意断开。

## 什么时候说明问题在存储层

如果你看到下面这些现象，通常要优先怀疑存储层：

- 应用写入失败
- 卷无法正常绑定或挂载
- 容量不足导致服务异常
- 数据丢失或目录内容异常
- 应用迁移后数据状态不一致
- Longhorn 卷状态不健康
- 快照数量异常或快照清理后空间没有按预期释放

这时继续只看应用日志通常不够，还需要回到 **存储分区**、卷状态、**快照管理** 和容量使用情况一起判断。

### 常见现象与检查方法

| 现象 | 先检查什么 |
| --- | --- |
| 分区一直显示 Pending | 表示仍在等待分配，检查可用空间和存储组件状态 |
| 应用不能写入 | 分区是否正常连接、是否空间不足、目录是否有写入权限 |
| 应用重建后文件不见了 | 数据目录是否真正使用了长期存储 |
| 删除快照后空间没有马上增加 | 可能还在清理，或相关数据仍被其他快照使用 |

删除分区、恢复数据或调整连接前，先备份重要内容，并确认没有选错应用。

## 使用存储管理时的建议

- 在正式应用上线前，尽早明确数据目录和持久化方式
- 对重要数据提前考虑备份策略
- 容量接近上限时尽早处理，不要等到应用报错再扩容
- 做迁移、恢复或删除前，先确认数据影响范围
- 出现问题时，不只看应用状态，也要同时看卷状态和底层存储状态

存储管理的价值，不只是让应用“有地方写数据”，而是让数据在应用长期运行过程中保持可用、可控、可维护。
