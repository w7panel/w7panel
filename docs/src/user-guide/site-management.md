# 站点管理

站点管理是一个可直接从应用商店安装的官方应用，用于在微擎面板中管理传统网站型业务。

它最重要的价值，不只是“新建一个站点”，而是解决这样一个问题：**在云原生架构下，如何继续兼容传统的“上传代码、配置域名、改 Nginx、维护运行环境”这套站点部署和维护方式。**

如果你的使用习惯更接近传统站点运维，而不是只部署一个通用容器应用，那么站点管理会更适合你。

## 这个应用能做什么

从当前能力看，站点管理主要覆盖下面几类事情：

- 新建、编辑、删除站点
- 绑定一个或多个域名
- 为站点开启 HTTPS
- 选择站点运行环境
- 修改站点 Nginx 配置
- 进入站点目录做文件维护
- 进入环境页继续维护运行环境

也就是说，它把“站点创建 → 代码目录 → 域名接入 → HTTPS → 环境维护”这条传统站点运维链路，整理到了面板里。

## 安装站点管理应用

在 **应用管理** 中打开应用商店，安装 **站点管理**，再进入它的管理页面。页面主要分为站点管理和环境管理，实际入口以安装的版本为准。

先确认网站需要哪种环境及版本。如果对应环境尚未安装，页面会提供“点击安装”。完成安装后再选择版本，不要随意用其他环境替代。

## 站点运行环境怎么理解

站点运行环境不是站点管理内部固定的一部分，而是以**独立的官方环境应用**形式发布和维护的。

常见环境类型包括以下几类，可安装版本以页面显示为准：

- PHP
- Python
- Node.js
- Go

站点管理负责的是“站点本身怎么创建、怎么接入、怎么配置”；具体运行环境，则由对应的环境应用继续维护。

需要注意的是，**环境页机制本身是通用的**，各类环境应用都可以接到这套机制里继续维护对应环境。只是目前 **PHP 环境** 的配置需求最复杂，所以当前提供了更完整的环境配置页面。

## 一、站点页适合做什么

站点页是最核心的入口，更偏向站点本身的创建和接入。

在这里，通常会处理：

- 新建站点
- 编辑站点
- HTTPS 配置
- 删除站点
- 站点目录跳转
- 环境选择
- Nginx 配置

### 新建站点时，几个字段怎么理解

创建站点时，最重要的几个字段通常是：

- **域名**：用户访问站点时使用的地址，可以填写一个或多个域名
- **目录**：站点文件实际存放的位置，用来放页面文件、静态资源和运行内容
- **环境**：站点运行所依赖的环境应用，例如 PHP、Python、Node.js、Go
- **备注**：用于记录站点用途、归属或特殊说明，方便后续管理

如果你是第一次创建站点，建议先把 **域名、目录、环境** 三项确认好，再去处理后续的 HTTPS 或 Nginx 配置。

### 多个域名和自动 HTTPS 怎么用

- 如果多个域名都要指向同一个站点，可以继续添加多个域名
- 如果某个域名需要自动 HTTPS，可以单独为该域名启用
- 如果只是临时测试站点，通常先配置一个主域名，确认访问正常后再补其他域名

这种做法更稳，因为先把主访问链路打通，再补充其他域名，排查问题会更容易。

### 环境怎么选

如果你已经知道站点运行语言，就优先选择对应环境：

- PHP 站点 → 选择 PHP 环境
- Python 站点 → 选择 Python 环境
- Node.js 站点 → 选择 Node.js 环境
- Go 站点 → 选择 Go 环境

不要只因为某个环境“更熟悉”就直接选择它。环境选错后，访问异常、启动失败或配置不生效的概率会明显增加。

### 什么时候需要改 Nginx 配置

以下场景通常需要进入 **Nginx 配置**：

- 站点访问规则需要细调
- 需要配置伪静态
- 需要补充或调整转发逻辑
- 默认配置已经不能满足当前站点需求

如果只是普通站点创建和基础访问，一般先用默认配置即可；只有当访问行为和预期不一致时，再去修改 Nginx 配置会更稳妥。

### 新建站点的完整步骤

1. 在站点管理中切换到网站需要的环境类型，点击 **新建站点**。
2. 填写域名，例如 `www.example.com`。输入框已有 `http://` 或 `https://` 前缀，不用重复填写；多个域名使用 **添加域名** 逐个添加。
3. 填写目录名称。页面前面的 `/www/wwwroot/` 已固定，例如填写 `example`，网站文件就放在 `/www/wwwroot/example`。
4. 选择已创建的环境，或从“新建环境”中选择版本并确认创建。
5. 如果页面要求启动命令，使用网站提供者给出的命令。网站文件尚未上传时，可以先开 **调试模式**，让环境保持开启以便上传；它不会启动网站程序。
6. 按需填写备注，点击 **确定**，等待环境启动。
7. 点击列表中的网站目录，打开文件管理并上传网站文件。只有创建网站、没有上传内容时，可能看到空白首页。
8. 如果之前开了调试模式，上传后重新编辑站点，关闭调试模式并填好启动命令，再保存。按页面显示的提示，到购买域名的平台设置域名解析，打开网址检查网站。

| 字段 | 怎么填写 |
| --- | --- |
| 域名 | 访问网站的名称；可为同一个网站添加多个域名 |
| 自动 https | 为相应域名申请安全访问证书，签发需要等待，且域名解析须正确 |
| 目录 | 网站文件所在的文件夹；不同网站尽量使用不同目录 |
| 环境 | 选择网站要求的软件和版本 |
| 启动命令 | 仅在页面要求时填写，请向网站提供者确认 |
| 备注 | 用容易识别的名称记录网站用途 |

保存网站资料、启动环境和准备好域名访问是几个步骤。看到“操作成功”后，仍应检查环境状态和网站能否打开。

### 使用示例：运行一个 PHP 页面

先安装并选择页面支持的 PHP 环境，准备自己的域名，例如 `www.example.com`：

1. 新建站点，域名填写 `www.example.com`，目录填写 `example`，选择已安装的 PHP 环境。
2. 创建完成后，点击网站目录，进入 `/www/wwwroot/example`。
3. 新建 `index.php`，填写以下内容并保存：

```php
<?php
echo '网站运行成功';
```

4. 按面板提示完成域名解析，通过浏览器打开网站，应看到“网站运行成功”。

这里不需要数据库或额外的业务程序。域名请替换成自己的；若目录已有网站，先备份并使用新的独立目录测试。完成后可换成网站提供者的完整文件，再按该网站说明配置数据库等内容。

### 上传文件和调整目录

点击站点列表中的目录，进入对应网站的文件管理。上传位置应与页面显示的目录一致；如果环境未启动，应先检查环境和启动命令。

替换网站文件前先备份。修改站点的“目录”会尝试把原目录中的文件搬到新目录，可能影响原路径及目标目录已有文件；这不只是修改显示名称。搬动前确认备份和新目录内容，保存后重新检查文件及网站。

网站需要数据库时，还需按网站自己的安装说明准备数据库和连接资料；新建站点不代表数据库已经配置好。

### 设置域名和证书

编辑站点的基础配置可以增加、修改或删除域名。每个域名都需要在域名服务商处正确设置解析。页面提示可能要求填写地址记录，也可能要求填写别名记录，按实际提示操作。

勾选 **自动https** 后，系统会尝试申请证书，不能保证保存后立即完成。列表中的 **https配置** 会打开面板的域名证书设置，详细操作见 [域名管理](./domain-management.md)。

开启自动 HTTPS 不等于自动把所有普通访问都跳转到安全网址。如果需要强制跳转，请在域名设置中核对对应选项。

### 应用 Nginx 配置前后如何检查

编辑站点时可进入 **Nginx配置**，它决定网站如何接收和处理访问请求。普通网站先保留默认内容；需要特殊访问路径或转发规则时，请网站开发者修改。

应用配置前先复制保存旧内容。应用后检查网站是否恢复正常；当前页面不会替你保证配置内容正确。站点共用的网站访问服务会重新启动，其他网站也可能短暂受影响。

### 删除站点和文件

删除确认框中：

- **删除站点配置**：必选，移除该站点的管理资料和访问配置。
- **删除站点文件**：可选，勾选后还会清理网站目录中的文件；普通站点不勾选时保留文件，关联应用的站点还需注意下方说明。

删除前备份网站文件和数据库。如果多个网站用了同一个目录，勾选删除文件会影响其他网站。不要在删除后立即往原目录放回文件，应先确认清理已结束。

部分站点由安装应用时自动建立，列表中会有 **应用管理**。删除此类站点还会发起关联应用的卸载；反过来，卸载关联应用也可能清理站点及文件。操作前确认关联关系，不能只因为未勾选“删除站点文件”就认定整个卸载过程会保留文件。

## 二、环境页适合做什么

环境页更偏向运行环境本身的维护，而不是站点接入。

可以简单理解成：

- **站点页**：处理域名、目录、环境选择、HTTPS、Nginx 配置这类“站点本身”的问题
- **环境页**：处理运行环境参数、扩展、日志、性能、配置项这类“环境本身”的问题

如果你发现问题发生在“站点怎么被访问”这一层，就先回站点页；如果问题发生在“程序怎么运行”这一层，就优先进入环境页。

如果你使用的是 PHP 环境，这部分能力通常会更完整；如果你使用的是 Python、Node.js 或 Go，则同样可以通过环境页机制接入对应环境应用，但具体可操作项以对应环境应用实际提供的能力为准。

### 环境的启动、配置和删除

进入 **环境管理**，可以新建环境、修改环境名称、启动、停止、重启、查看日志和进入环境配置。

- **运行中**：环境已启动，仍需实际打开网站检查业务是否正常。
- **启动中**：等待完成；长时间不变时请管理员检查启动情况。当前环境列表只有“运行中”时才显示日志、终端和配置按钮。
- **已停止**：尝试启动，并检查网站启动命令和错误提示。

页面会说明所选类型是否允许多个站点共用环境。共用环境的站点会一起受到停止、重启和配置修改的影响，操作前查看“站点数量”。不能共用的类型应给每个站点选择独立环境。

环境正在被站点使用时不能删除，应先调整或删除相关站点。删除环境还会清理它的运行文件；删除最后一个同组环境时，还可能移除对应的环境应用，请先确认影响范围。

#### 配置环境

点击环境后的齿轮按钮进入 **环境配置**。直接打开某个环境应用的首页时，可能只看到操作指引，应回到站点管理的环境列表选择具体环境。

PHP 环境提供扩展安装、配置文件、性能调整、禁用函数、日志、慢日志和负载状态等页面。其他环境的选项不同，不一定有这些功能。

- 扩展：仅安装网站要求的项目，按当前环境提供的列表选择；能否启用、禁用或卸载以对应按钮为准。
- 日志：需要时打开开关并刷新。慢日志用于查看处理较慢的请求，与网站页面错误不是同一种记录。
- 性能调整、禁用函数和自定义环境：会影响程序运行，不确定时请网站开发者协助。

安装扩展或保存自定义环境后，可能需要等待处理和重启完成。更换环境或重新安装前，请另行保存重要配置，不要假定所有修改都会自动保留。

## 三、常见使用链路

如果你是第一次使用站点管理，通常可以按下面顺序操作：

1. 在应用商店安装 **站点管理**
2. 新建站点
3. 配置域名、目录和环境
4. 根据需要开启 HTTPS
5. 进入站点目录查看或维护文件
6. 如果需要进一步调整运行环境，再进入环境页
7. 如果访问规则有特殊要求，再进入 Nginx 配置继续处理

这条链路基本覆盖了一个站点从创建到可访问、再到持续维护的主要过程。

## 四、什么时候优先检查站点管理本身

如果你遇到下面这些情况，通常要先回到站点管理应用里检查：

- 站点创建后打不开
- 域名绑定后访问异常
- HTTPS 没有按预期生效
- 环境选择错误导致站点行为异常
- Nginx 配置修改后访问结果不符合预期

### 排查步骤

1. 查看环境是否运行；如果开启了调试模式，关闭后填写正确启动命令。
2. 点击目录确认文件已上传，首页文件位于网站要求的位置。
3. 核对环境及版本是否符合网站要求，查看环境日志中的错误。
4. 核对域名解析，安全网址还要检查证书是否已签发。
5. 如果刚修改目录、域名或访问配置，确认相关修改均已完成，再刷新页面检查。

保存失败或网站仍异常时，先查看列表和目录的实际结果，再决定是否重试，避免重复创建环境或覆盖文件。

## 使用建议

- 新建站点前，先规划好域名、目录和环境
- 如果站点依赖 HTTPS，建议在绑定域名时一起处理
- 修改 Nginx 配置或环境参数前，先确认影响范围
- 如果站点异常，不要只看站点页，也要同时检查环境页、日志和目录内容

站点管理的价值，在于把传统“上传代码就能跑”的站点模式，更自然地接到云原生架构和面板能力里。
