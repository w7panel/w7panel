# 应用管理

应用管理用于创建、查看和维护已经部署到集群里的应用。对大多数用户来说，这里是进入面板后最常用的页面之一。

在当前面板里，应用管理相关的常见页面包括：

- **应用列表**
- **传统应用**
- **轻量虚拟机**
- **添加应用**
- **应用商店**
- **云端应用商店**
- **应用详情**
- **监控**
- **文件管理**
- **域名管理**
- **计划任务**
- **反向代理**

## 进入应用管理

1. 登录微擎面板。
2. 在左侧菜单进入 **应用管理**。
3. 根据应用类型打开 **应用列表**、**传统应用** 或 **轻量虚拟机** 页面。

三个列表沿用相同的管理界面，都会展示应用名称、创建时间、访问相关信息以及可进入的常用操作入口，但展示范围不同：

| 菜单 | 展示范围 |
|------|----------|
| 应用列表 | 兜底展示普通应用、没有类型标签及尚未独立管理的其他类型，不包含传统应用和系统镜像 |
| 传统应用 | 按传统网站方式安装和维护的应用 |
| 轻量虚拟机 | 提供独立系统环境的应用 |

面板会根据应用类型将它们放到对应列表；找不到应用时，先核对列表类型和当前选择的命名空间（项目分区）。

网关插件和应用插件不会作为独立应用出现在这里。应用插件提供的功能会聚合到它所依赖的普通应用详情中。

从传统应用中的“授权与续费”进入关联插件订单后，可以检测插件新版本、前往面板升级或确认卸载；脱离面板单独打开市场页面时，升级和卸载会提示返回面板操作。

## 新建应用

在 **应用列表** 页点击 **新建** 后，可以根据应用来源选择不同创建方式。

在 **传统应用** 页点击 **新建**，会进入制品市场并固定筛选“传统应用”分类；在 **轻量虚拟机** 页点击 **新建**，会进入制品市场并固定筛选“系统镜像”分类。安装完成后，对应应用会显示在各自的专用列表中；专用制品市场、制品安装页和应用详情面包屑中的 **应用管理**，以及完成页的 **返回列表**，也会按入口或应用类型返回普通应用、传统应用或轻量虚拟机列表。

常见入口包括：

- **应用商店**：适合快速安装常见应用
- **云端应用商店**：适合从云端应用入口选择可安装内容
- **Docker Compose**：适合已有 Compose 配置的应用
- **K8s YAML**：适合直接提交 Kubernetes 资源清单
- **Helm**：适合使用 Helm Chart 安装
- **代码包 / 构建型方式**：适合需要构建镜像或上传代码包的场景

### 选择方式的建议

如果你不确定该用哪种方式，可以先按这个思路判断：

| 场景 | 推荐方式 |
|------|------|
| 想快速安装已有应用 | 应用商店 |
| 想从云端入口选择可安装内容 | 云端应用商店 |
| 已经有 Compose 文件 | Docker Compose |
| 已经有 K8s YAML | K8s YAML |
| 已经有 Helm Chart | Helm |
| 需要结合代码包、构建或镜像处理 | 代码包 / 构建型方式 |

## 通过应用商店或云端应用商店创建应用

安装和更新需要创始人账号权限。遇到权限提示时，先确认当前账号。

1. 点击 **新建** → **应用商店** 或 **云端应用商店**。
2. 选择目标应用。
3. 按页面提示填写安装参数。
4. 确认命名空间、应用名称、访问方式、存储和资源限制等信息。
5. 点击安装或创建，等待应用部署完成。

如果应用带有额外配置项，建议先完整检查一次，再提交安装，避免后续反复修改。

### 安装时常见字段

| 字段 | 怎么理解 |
| --- | --- |
| 应用名称 | 用来区分不同应用，建议填写容易识别的名称 |
| 命名空间 | 应用归属的项目分区，后续查看时应选择同一区域 |
| 镜像 | 应用的程序包地址；商店应用通常已经提供 |
| 端口 | 应用接收访问的位置，按应用说明填写 |
| 存储 | 数据放在哪里；数据库、上传文件等重要内容需要长期保存 |
| 资源限制 | 允许应用使用的处理器和内存，过小可能导致启动失败 |

若你拿到的是 Compose、K8s YAML 或 Helm 配置，请选择对应的安装方式。这些是开发者准备的安装配置，建议由提供配置的人协助填写，不必为了使用商店应用学习这些格式。

## 通过 Compose / YAML / Helm 创建应用

如果你使用的是 Compose、YAML 或 Helm，一般可以按下面的顺序操作：

1. 选择对应创建方式。
2. 粘贴或上传配置内容。
3. 填写命名空间、名称和必要参数。
4. 确认应用使用的端口、镜像、存储和访问入口。
5. 提交创建并等待面板完成部署。

如果创建完成后应用状态异常，优先去应用详情页看运行状态、日志和事件。

## 查看应用详情

在 **应用列表** 中点击目标应用后，通常可以进入 **应用详情** 页。

在 **应用详情** 页里，常见会用到这些入口：

- **应用详情**：查看应用基础信息和整体状态
- **监控**：查看应用运行相关信息
- **文件管理**：进入应用目录维护文件和配置
- **域名管理**：配置访问入口和 HTTPS
- 其他与当前应用相关的后续维护入口

应用附带的功能会出现在详情菜单中；多个功能来源可能按名称分组展示。

付费制品可能在应用详情顶部显示 **服务中心**。该入口仅创始人可见；没有对应订单菜单的免费应用不会显示该分组。

如果你只停留在 **应用列表**，很多问题是看不出来的；需要进一步排查时，通常要进入 **应用详情** 或相关子页面。

## 卸载应用

1. 确认要卸载的应用，并备份需要保留的数据。
2. 点击卸载，仔细核对确认提示中受影响的应用。
3. 确认后等待处理完成，不要重复点击。

如果其他应用依赖它，面板会查找关联应用，并一并提交卸载。删除过程中可能出现部分应用已提交删除、其他应用处理失败的情况。页面提示删除成功后，后台可能仍在清理，刷新确认相关应用是否已移除。卸载应用不等于备份数据，数据是否保留要看安装配置和删除提示。

## 计划任务和反向代理

计划任务位于 **应用管理**，反向代理位于 **网关管理**，可以按用途选择：

- **计划任务**
- **反向代理**

如果你的目标不是“创建一个新应用”，而是“让已有服务按某种方式被访问”或“让某些工作定时自动执行”，通常就应该进入对应专题继续查看：

- [计划任务](./scheduled-tasks.md)
- [反向代理](./reverse-proxy.md)

## 应用创建后最常见的操作

应用创建完成后，最常见的后续操作通常是：

1. **确认应用是否启动成功**
2. **配置域名和访问入口**
3. **查看日志和事件**
4. **进入文件管理修改配置或上传内容**
5. **进入域名管理配置访问入口**
6. **根据需要继续升级或调整应用参数**

这也是为什么应用管理不只是“新建应用”，而是整个应用维护入口。

## 什么时候优先看应用日志和事件

如果你遇到下面这些情况，通常应该优先回到 **应用详情** 页里的运行状态、日志和事件入口：

- 应用创建后一直没有正常运行
- 页面显示部署成功，但访问异常
- 应用状态反复变化或容器不断重启
- 修改配置后行为不符合预期

日志更适合看程序本身的报错，事件更适合看 Kubernetes 调度、挂载、拉镜像和资源层面的异常。

## 什么时候要进入文件管理或域名管理

### 进入文件管理的常见场景

- 要修改配置文件
- 要上传静态资源、脚本或备份文件
- 要查看应用目录内容
- 要调整文件权限

### 进入域名管理的常见场景

- 要给应用绑定访问域名
- 要开启 HTTPS
- 要调整访问路径或转发规则
- 要排查“应用已运行但外部打不开”这类问题

## 应用访问异常时的排查顺序

如果应用“创建成功但访问不正常”，建议按下面顺序判断：

1. 应用本身是否已经启动成功
2. 日志里是否有明显报错
3. 事件里是否提示调度、挂载或拉镜像失败
4. 域名和访问入口是否配置正确
5. 文件配置是否缺失或写错

不要一开始只盯着域名，也不要只盯着应用状态，最好把运行状态、日志、文件和访问入口一起看。

### 常见现象与处理

| 现象 | 先检查什么 |
| --- | --- |
| 安装后一直没有运行 | 看事件提示；检查程序包能否下载、服务器资源是否足够 |
| 状态正常但打不开 | 检查域名解析、访问端口和证书 |
| 修改配置后没变化 | 确认改的是该应用正在使用的配置，按应用说明重新加载或重启 |
| 应用反复重启 | 看日志，确认配置完整、内存够用 |
| 卸载没有完成 | 查看失败提示，处理关联应用或存储问题后再继续 |

## 使用应用管理时的建议

- 创建应用前先明确最适合的交付方式
- 创建完成后优先确认状态、日志和域名
- 需要长期维护的应用，尽量把文件、域名和存储一起规划
- 出现问题时，不只看“应用有没有创建成功”，而要看它是否真的能运行、能访问、能维护

应用管理的重点不是把应用“加进去”，而是把应用真正“用起来、管起来”。

## 更新应用

看到新版本提示后，先阅读更新说明，备份重要数据，再按页面提示更新。更新后重新检查状态和访问结果。传统应用的关联插件也可以从 **授权与续费** 中检查版本并前往面板升级。
