# 微擎面板是什么

微擎面板（W7Panel）是一套面向 Kubernetes 场景的云原生应用管理平台。你可以把它理解为一个统一的控制台：把原本分散在命令行、配置文件和多个工具里的工作，尽量收拢到一个更直观、更适合日常使用的界面中。

它不是用来替代 Kubernetes 的，而是帮助用户更轻松地使用 Kubernetes。对很多团队来说，真正困难的地方不是“这些能力做不到”，而是“这些能力太分散、太底层、不适合高频日常操作”。微擎面板要解决的，就是把这些事情变得更顺手、更集中、更容易管理。

## 它能帮你做什么

如果只用一句话来概括，微擎面板做的是：**把应用从部署、接入、维护到排查这一整条链路，尽量放到一个地方完成。**

围绕这个目标，它把日常最常用的几类工作集中到了一起：

- 查看集群和资源状态
- 部署和管理应用
- 维护文件和配置
- 处理域名、访问入口和 HTTPS
- 管理存储和持久化数据
- 查看日志、事件和运行状态，做日常排查

也就是说，它不只是“把服务部署上去”的工具，而是一个围绕应用持续运行而设计的管理入口。

## 它为什么会更有辨识度

微擎面板比较有辨识度的地方，主要体现在下面这些能力上：

- **应用机制**：把应用从单纯的镜像或 YAML，提升成更适合安装、分发、管理和持续维护的交付单元。
- **应用商店**：提供统一的应用入口，方便快速安装和接入常见应用。
- **应用管理页面**：应用可以把自己的功能菜单接入面板，方便在同一处使用。
- **私有 DNS 与集群内访问能力**：兼顾集群内服务访问、内部解析、代理和连接诊断。
- **本地镜像管理**：支持围绕集群本地镜像做查看、导入、整理、提交和相关管理。
- **文件管理能力**：把文件浏览、在线编辑、上传下载、压缩解压和权限调整直接带进面板。
- **节点侧运维能力**：覆盖一部分更贴近日常运维的节点侧操作和运行资源处理。

这些能力放在一起，让微擎面板更像一套把应用交付、接入、维护和运维串起来的完整控制台。

## 它和传统服务器面板有什么不同

传统服务器面板通常更适合单机环境，重点在网站、数据库、系统服务和本地文件管理。微擎面板则更偏向云原生应用场景，核心基础是 Kubernetes。

简单理解：

- 传统面板偏单机运维
- 微擎面板偏云原生应用运维

它关注的不只是“服务有没有跑起来”，还包括应用怎么交付、怎么接入、怎么维护、怎么排查，以及数据和存储怎么一起管理。

## 它适合哪些用户

微擎面板通常适合以下几类用户：

- **个人开发者**：希望更轻松地部署和管理自己的应用
- **中小团队**：希望把应用、文件、域名、存储和运维入口统一起来
- **运维或平台团队**：希望给研发、测试或业务侧提供更低门槛的 Kubernetes 操作界面
- **私有化部署场景**：希望自己掌控应用、数据和运行环境

如果你的目标是继续使用 Kubernetes，但不想让日常操作完全依赖底层命令，那么微擎面板会很合适。

## 第一次使用时，怎么理解它最合适

你可以把微擎面板理解成这样一条连续链路：先接入并查看运行环境，再创建和交付应用，然后配置访问方式，接着维护文件、域名和存储，最后在运行过程中持续查看状态、处理问题和做日常运维。

所以它看起来不只是一个“应用部署页面”，而是一个把部署、接入、维护和排查串起来的完整管理平台。

## 页面上的几个名称

- **应用**：你安装和使用的程序，例如网站、数据库。
- **集群**：一起运行应用的一组服务器，也可以只有一台。
- **节点**：集群中的一台服务器。
- **命名空间**：把不同项目的应用和配置分开管理的区域。列表找不到内容时，先检查当前选择的区域。
- **镜像**：启动应用需要的程序包。
- **存储分区**：给应用保存文件和数据的空间。
- **HTTPS**：网址以 `https://` 开头的加密访问方式。

## 为什么我的菜单和文档不同

菜单和操作按钮会受到账号权限、已安装应用及组件的影响。有些功能需要先安装对应应用。看不到入口时，请先联系面板管理员确认权限和安装情况。
