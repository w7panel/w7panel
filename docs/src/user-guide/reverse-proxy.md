# 反向代理

反向代理用于把外部请求转发到目标服务。它更适合处理“已有服务怎么被访问”这类问题，而不是“如何创建一个新应用”。

如果目标是统一接入 DeepSeek、OpenAI、通义千问或自建 vLLM 等大模型 API，并需要消费者认证、模型限制或多提供者权重，请改用 [AI 代理](./ai-proxy.md)。

在当前面板里，反向代理不仅有独立的 **反向代理** 列表页，还有对应的 **域名管理** 子页，用来继续处理反向代理自身的访问入口配置。

## 进入反向代理

1. 登录微擎面板。
2. 进入 **网关管理 → 反向代理**。
3. 已有代理可从列表进入对应的 **域名管理**，继续设置访问入口。

## 适合什么场景

常见场景包括：

- 把外部请求转发到内部服务
- 为已有服务补充统一访问入口
- 让某个路径指向指定目标地址
- 按路径拆分不同后端服务

如果你的目标不是“部署一个新应用”，而是“让已有服务按某种方式被访问”，通常反向代理会更合适。

## 新建反向代理

1. 进入 **网关管理 → 反向代理**，点击 **新增**。
2. 填写访问域名和转发目标地址，按页面要求设置端口等选项。
3. 保存后，在该条目中进入 **域名管理**。
4. 按提示配置域名解析，需要加密访问时配置 HTTPS 证书。
5. 进入域名管理确认访问域名已出现在列表，再使用实际域名打开页面，检查首页、登录和图片是否都能正常使用。

如果显示操作成功但域名没有出现，可能是代理目标已保存、域名尚未成功添加。请检查权限和错误提示，再补充域名，避免重复创建代理。

### 操作前准备

- 确认目标服务已经正常运行，并能从面板所在环境连接。
- 准备访问域名，并能在域名服务商处修改解析记录。

### 使用示例：通过域名访问已有网站

假设现有网站地址是 `http://192.0.2.10:8080`，希望通过 `www.example.com` 访问：

| 内容 | 填写方式 |
| --- | --- |
| 访问域名 | `www.example.com` |
| 目标协议 | `http` |
| 目标地址 | `192.0.2.10` |
| 目标端口 | `8080` |

如果页面将转发目标合并为一个输入框，则填写完整的 `http://192.0.2.10:8080`。示例地址需换为实际服务地址，不能填成代理自身的域名，以免重复转发。

保存后将 `www.example.com` 解析到网关入口，而不是直接解析到上述目标地址；入口地址以面板提示为准。先检查网页、图片与登录，再按 [域名管理](./domain-management.md) 开启 HTTPS。

## 路径规则什么时候重要

如果一个域名下不只承载一个简单页面，而是：

- 主站和 API 分开
- 不同路径对应不同服务
- 静态资源和动态请求分开

这时路径规则就非常关键。

如果页面能打开，但资源加载错乱、接口请求异常或某些路径返回不对，通常要优先检查路径规则。

## 编辑或删除反向代理

列表中可以编辑目标地址、进入域名管理或删除代理。删除后应刷新列表，并到域名管理核对不再使用的域名是否仍有残留。代理停止转发后，仍需要另行安排目标服务的访问方式。

## 访问异常时怎么判断

如果通过反向代理访问异常，建议先按这个顺序判断：

1. 目标服务本身是否正常运行
2. 域名或入口是否已经接通
3. 路径规则是否配置正确
4. 请求是否被转发到了正确目标

很多“反向代理有问题”的情况，最后并不是代理本身坏了，而是目标服务、路径配置或访问入口没有对齐。

### 常见现象与处理

| 现象 | 检查方法 |
| --- | --- |
| 完全打不开 | 确认域名指向正确服务器，目标服务能从面板环境访问 |
| 打开的是其他网站 | 核对域名和转发目标 |
| 首页正常，图片或登录失败 | 检查路径和目标应用的访问地址设置 |
| 浏览器提示证书问题 | 检查域名对应的证书是否有效 |

需要统一接入大模型服务，请阅读 [AI 代理](./ai-proxy.md)；需要限制网站访问，请阅读 [网关插件](./gateway-plugins.md)。

## 使用反向代理时的建议

- 先确认目标服务本身可用，再配置代理
- 一个域名对应多个服务时，要优先规划路径规则
- 修改线上代理前，先确认会影响哪些现有访问路径
- 遇到问题时，不只看入口本身，也要看目标服务是否真的正常返回

反向代理的价值，在于把已有服务更稳定地接到访问链路上。
