# CDN 文件缓存

本应用需要另行安装，具体字段以已安装版本为准。**源站**指提供原始文件的网站，**回源**指缓存没有文件时再向原网站获取。

CDN 文件缓存是一个官方应用，用于在微擎面板中管理静态资源的缓存加速能力。它适合处理“如何让站点静态资源更快分发出去，并通过缓存规则降低源站压力”这类场景。

项目已开源：

- https://github.com/w7panel/w7panel-cdncache

## 这个应用能做什么

从当前前后端能力看，CDN 文件缓存主要覆盖下面几类事情：

- 为一个或多个域名开启文件缓存能力
- 配置源站地址和回源 Host
- 设置缓存规则和缓存时间
- 设置缓存键规则
- 查看域名列表和当前缓存配置
- 手动清空缓存
- 配合域名解析把缓存入口真正接通

如果你的目标是让站点中的图片、JS、CSS 等静态资源更快访问，同时希望在面板里集中维护缓存规则和源站配置，这个应用会更合适。

## 一、从哪里开始最合适

1. 安装并打开 **CDN 文件缓存** 应用。
2. 请管理员先准备缓存保存位置，在 **全局存储配置** 中保存连接资料。
3. 回到站点列表，点击 **添加站点**，填写访问域名。
4. 按页面提示完成域名解析。
5. 点击该站点的 **修改**，先检查 **存储配置**，再填写 **缓存配置** 中的源站和规则。
6. 点击 **保存**（独立打开页面时为 **保存配置**），重新进入核对，并实际访问文件。

### 添加域名之前先准备什么

- 一个能修改解析记录的域名，例如 `static.example.com`。
- 原始文件地址，例如 `https://origin.example.com/images/logo.png`，并确认文件可以正常下载。
- 用于保存缓存的存储连接资料，由管理员提供；源网站地址不能替代存储地址。

“全局存储”是多个站点可以共用的一套保存设置。没有配置时，即使域名已创建，也不能正常完成文件缓存。

## 二、域名列表页可以做什么

列表提供 **添加站点**、**修改**、**清空缓存**、**https配置** 和 **删除**。

### 新增域名

1. 点击 **添加站点**，填写自己的域名，不附加页面路径。
2. 多个访问域名可逐个添加；需要安全访问时按域名开启自动 HTTPS。
3. 提交后刷新，核对域名是否出现，再进入 **修改** 完成源站和存储配置。
4. 自动申请证书需要正确解析；保存成功不表示证书已经签发。

多个域名可能共用一份站点配置，修改前核对关联域名。创建、保存设置和删除访问入口分步处理，出现错误时先检查列表和已有设置，避免重复添加。

删除站点会移除缓存配置和关联访问入口，不能据此认为缓存存储中的所有文件都已删除；清理存储请管理员另行确认。

## 三、DNS 解析提示怎么理解

添加域名后，页面会显示解析提示。按提示到域名服务商处添加对应记录，让访问经过缓存入口。

这意味着：

- 在面板里添加域名只是第一步
- 真正接通访问链路，还需要把域名解析到正确的缓存入口

如果域名已经添加成功，但访问没有经过缓存，通常要优先检查解析记录是否已经按提示配置正确。

## 四、缓存配置页可以做什么

站点详情分为 **缓存配置** 和 **存储配置** 两个页签。

| 页签 | 配置内容 |
| --- | --- |
| 缓存配置 | 节点缓存过期配置、缓存键规则配置、源站信息配置 |
| 存储配置 | 选择全局配置或自定义，并确认缓存保存到哪里 |

### 存储配置怎么填

首次使用请管理员准备兼容 S3 的存储，也就是能够保存这些缓存文件的服务：

| 页面字段 | 含义 |
| --- | --- |
| access_key | 存储访问账号标识 |
| secret_key | 对应访问密钥，不要公开 |
| bucket | 保存文件的空间名称，由管理员提供 |
| host | 存储服务地址，使用应用能够访问的内网地址，并核对 http 或 https |
| 地区 | 存储服务要求的区域名称 |

选择 **全局配置** 时继承连接资料，站点可以单独填写 `bucket`；留空时使用全局的空间名称。选择 **自定义** 时为当前站点填写完整资料。

多个站点若使用同一个保存空间，还需确认同名文件不会互相影响。修改全局连接会影响继承它的站点，建议管理员规划独立空间。

## 五、先调哪一类配置最合适

1. **先确认存储**：连接资料和保存空间必须正确。
2. **再配源站信息**：确认缓存服务可以取得原文件。
3. **再配缓存规则**：决定哪些文件缓存、保存多久。
4. **最后调整缓存键规则**：只有清楚网址参数的用途时再修改。

保存后重新打开页面核对，不要一次修改所有设置，便于出现问题时判断原因。

## 六、缓存规则怎么理解

在 **节点缓存过期配置** 点击 **添加**，按需要填写：

| 字段 | 含义与示例 |
| --- | --- |
| 是否缓存 | 打开才会保存匹配文件的缓存；关闭表示这条规则匹配的内容不使用缓存 |
| 缓存时间(分钟) | `5` 表示五分钟，`0` 表示不自动过期，不是关闭缓存 |
| 类型 | 当前表单可选全部文件、文件后缀、文件目录 |
| 路径 | 文件目录例如 `images/`；文件后缀例如 `.png`，输入后回车，可填多项 |
| 权重 | 普通匹配规则中数值越小越先检查，例如 `1` 先于 `10` |
| 流式返回 | 允许下载时分段返回内容；不确定时保留默认值 |

“全部文件”作为其他规则没有匹配时的兜底设置，不能仅靠给它更小的权重覆盖目录或后缀规则。目录按开头文字匹配，建议使用 `images/`，避免 `images` 同时匹配到其他类似名称。

例如：图片目录开启缓存，时间 `5` 分钟；再增加“全部文件”并关闭缓存，避免把其他内容也保存起来。登录页面、个人资料、订单和用户专属内容不要套用公共文件缓存规则。

## 七、缓存键规则怎么理解

缓存键规则决定：网址不同的时候，是否仍使用同一份缓存。例如 `logo.png?size=small` 与 `logo.png?size=large` 是否应该分开保存。

| 忽略参数选项 | 含义 |
| --- | --- |
| 不忽略 | 保留全部网址参数，初次配置建议采用 |
| 全部忽略 | 参数不同也可能使用同一份缓存 |
| 忽略指定参数 | 只去掉明确不影响内容的参数 |
| 保留指定参数 | 只用填写的参数区分文件 |

需要指定参数时填写参数名，例如 `size`，输入后回车，不要填完整网址。“忽略大小写”用于这条规则匹配路径，不应当作网站所有地址自动合并大小写的保证。

图片尺寸、下载权限或文件版本由参数决定时，不能随意忽略它们。不了解参数用途时保留“不忽略”，避免访问到错误内容。

## 八、源站信息配置

**源站地址**填写真正提供文件的网站。页面已提供协议选择，例如选择 `https://`，右侧填写 `origin.example.com`，不要重复输入协议。

**源站HOST**用于原网站按域名识别网站的情况：需要时打开开关，填写 `origin.example.com`，不附带协议和路径；不需要时关闭，按源站地址访问。

源站不能填写当前缓存域名自身，避免重复转发。原文件位于 `/images/logo.png` 时，缓存域名也按该路径访问；先核对源网站能正常下载该文件。

## 九、清空缓存什么时候会用到

原文件更新后仍看到旧内容时，可以清理对应路径的缓存：

1. 在站点列表找到正确域名，点击 **清空缓存**。
2. 在 **路径** 中填写文件路径，例如 `/images/logo.png`；需要清理整个目录时填写 `/images/`。
3. 确认后重新访问文件，必要时同时刷新浏览器缓存。

当前清理按路径开头匹配。例如 `/images/` 会处理该目录下的缓存，不是只清理一个文件。空路径和 `/` 不能用于一键清空全部缓存，请填写明确的文件或目录路径。

带参数的文件可能保存为不同缓存名称，原网址路径不一定直接匹配到所有副本；需要时确认影响范围后按所属目录清理。

清理的是服务端存储，浏览器已经保存的副本不会一起消失；特别是“不自动过期”的内容，还可能需要使用新文件名或按正确参数规则更新访问地址。清理后重新下载会增加原网站的访问量。

## 十、常见使用链路

### 使用示例：为图片目录配置五分钟缓存

假设原图片是 `https://origin.example.com/images/logo.png`，缓存访问地址为 `https://static.example.com/images/logo.png`：

1. 请管理员配置全局存储，准备当前站点的保存空间。
2. **添加站点**，填写 `static.example.com`，按提示解析并检查需要的 HTTPS 证书。
3. 点击 **修改 → 存储配置**，选择全局配置，核对保存空间。
4. 进入 **缓存配置 → 源站信息配置**，协议选择 `https://`，地址填写 `origin.example.com`；源网站需要时再设置源站 HOST。
5. 在节点缓存规则中添加“文件目录”，填写 `images/`，打开缓存，时间填写 `5`，权重填写 `1`。
6. 再添加“全部文件”规则，关闭缓存，作为其他文件的兜底设置；缓存键先保留网址参数。
7. 点击 **保存**，重新进入核对。访问缓存图片地址，应与原图片一致。
8. 更新原图片后，需要马上刷新时，在列表清理 `/images/`，再重新访问验证。

以上域名和存储空间需替换成自己的。网页能打开只说明文件能够取得；是否已经保存缓存，还需结合存储中对应文件或管理员查看的访问记录确认。

## 十一、什么时候优先检查这个应用本身

| 现象 | 检查方法 |
| --- | --- |
| 提示尚未配置全局存储 | 先由管理员保存全局存储资料，或为本站点配置自定义存储 |
| 提示附件源或缓存存储配置错误 | 检查源站、保存空间和存储连接，不要只修改域名解析 |
| 文件可以下载但没有缓存 | 检查规则是否匹配、是否开启，以及保存空间能否写入 |
| 清理后仍看到旧内容 | 确认原文件已更新，清理路径是否正确，浏览器是否仍在使用旧副本 |
| 图片尺寸或内容不对 | 检查是否错误忽略了影响内容的网址参数 |
| HTTPS 访问失败 | 查看域名解析及证书签发结果 |

保存或删除途中失败时，先核对域名列表、配置和实际访问结果，再决定是否重试。

## 使用建议

- 首次接入先选一个公共文件目录测试，再扩大范围。
- 缓存时间单位是分钟，不能把秒数直接填进去。
- 保存设置、访问正常和缓存成功分别核对。
- 存储连接和复杂规则由管理员提供；日常更新按文件或目录清理缓存。

应用源码见 [w7panel-cdncache](https://github.com/w7panel/w7panel-cdncache)。
