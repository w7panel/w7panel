# 域名管理

域名管理用于把应用从“已经运行”推进到“能够被稳定访问”。很多时候，应用创建成功只是第一步，真正影响使用体验的，是域名、访问入口和 HTTPS 是否配置正确。

在当前面板里，和访问入口相关的常见页面或能力包括：

- **域名管理**
- **证书管理**
- **反向代理**

如果你的应用已经部署成功，但浏览器无法访问，或者 HTTPS、路径转发、域名解析存在问题，通常就应该优先回到这些入口处理。

## 进入域名管理

域名通常是从应用详情页进入管理的。

常见步骤：

1. 进入 **应用管理**。
2. 打开目标应用详情。
3. 点击 **域名管理**。

域名管理更适合处理某个应用自己的访问入口；如果问题已经超出单个应用，比如涉及统一证书或转发链路，通常还要进一步看 **证书管理** 或 **反向代理**。

## 添加域名

### 基本操作步骤

1. 点击 **添加域名**。
2. 输入域名地址。
3. 选择是否启用 HTTPS。
4. 选择证书方式。
5. 确认保存。

添加完成后，还要确认域名解析和访问入口是否真正生效。

### 什么时候需要配置域名

以下场景通常都需要域名：

- 网站或控制台要正式访问
- 应用接口要有固定入口
- 同一个应用要对外提供稳定地址
- 需要启用 HTTPS

如果应用只是在内部测试，域名可能不是第一优先级；但一旦涉及正式访问，域名管理通常就是必做步骤。

## HTTPS 配置

在微擎面板里，域名和 HTTPS 通常是一起处理的。

### 常见证书方式

- **自动申请**：适合标准公网域名场景，配置更省事
- **手动上传**：适合已有现成证书，或需要自定义证书来源的场景

### 启用 HTTPS 的建议顺序

1. 先确认域名解析已经正确生效。
2. 再选择自动申请或手动上传证书。
3. 最后确认 HTTPS 是否已经能正常访问。

如果你一开始就先看证书，但域名解析本身都没通，往往会浪费很多时间。

## 证书管理什么时候会用到

如果你的关注点已经不只是“单个应用能不能开 HTTPS”，而是：

- 证书是否有效
- 证书是否即将过期
- 证书是否需要统一替换
- 不同应用的证书是否正常生效

这时通常就要进一步进入 **证书管理** 处理。

可以把它理解成：

- **域名管理** 更偏“给某个应用接入口”
- **证书管理** 更偏“处理 HTTPS 证书本身”

## 路径和转发规则

一个域名不一定只对应一个简单入口。很多应用会有：

- 主站和 API 分开
- 静态资源和动态请求分开
- 一个域名下挂多个路径

这时就需要通过路径和转发规则，把不同请求指向正确的目标服务。

### 常见适用场景

- 网站和 API 分开转发
- 一个域名下挂多个服务路径
- 某些静态资源路径需要单独处理

如果域名能打开，但页面内容不对或接口报错，通常要回头检查路径和转发规则。

## 反向代理什么时候会用到

如果你的目标已经不只是“给应用绑一个域名”，而是要处理更灵活的转发规则或统一访问入口，请直接查看：

- [反向代理](./reverse-proxy.md)

## 网关插件规则

域名策略中的 **更多** 用于配置网关插件规则。这里只显示已安装且勾选“支持规则配置”的插件；网关列表中的全局状态不会隐藏该入口，卸载插件后入口才会消失。

选择插件后，按照页面中的配置项填写并保存即可；官方应用提供的插件会在标题右侧显示 **官方** 标识。配置界面右上角可通过 **YAML 详情** 查看和编辑当前规则。没有关联到可用配置页面或操作界面加载失败时会直接进入同一个 YAML 只读预览，点击 **编辑** 后才能修改。插件的安装、全局配置和启停操作请前往 [网关插件](./gateway-plugins.md)。

域名的 Host/Path 重写由 Ingress 自身配置负责，不会改写网关插件的私有配置。删除域名或路径时，系统会同步移除插件规则中的对应 Ingress 引用。

## 域名访问异常时先看什么

如果域名无法访问，建议先按这个顺序判断：

1. 域名是否已经正确解析
2. 应用本身是否已经正常运行
3. 访问入口或路径规则是否配置正确
4. HTTPS 证书是否已经生效
5. 是否需要进一步检查反向代理或集群内访问链路

很多“域名打不开”的问题，最后并不是域名本身的问题，而是应用状态、入口配置、证书状态或转发链路的问题。

## 域名管理里最常见的误区

比较常见的误区包括：

- 以为应用运行了，域名就一定能访问
- 只配了域名，没有确认解析是否真正生效
- 开启了 HTTPS，但证书还没有生效
- 配了路径规则，但没有确认目标服务是否正确

域名管理的关键，不在于“配置动作做了没有”，而在于“从外部访问时整条链路是否真的通了”。

## 什么时候说明问题可能不只在域名页

如果你已经确认域名配置没明显问题，但访问还是异常，通常要进一步回到这些地方继续查：

- 应用运行状态
- 日志和事件
- 证书管理
- [反向代理](./reverse-proxy.md)
- 集群入口或服务转发状态
- [私有 DNS](./private-dns.md)

域名管理的价值，是把应用接到可访问状态；如果接不通，它也是定位访问链路问题的重要入口。
