# 域名管理

域名管理用于把应用从“已经运行”推进到“能够被稳定访问”。很多时候，应用创建成功只是第一步，真正影响使用体验的，是域名、访问入口和 HTTPS 是否配置正确。

在当前面板里，和访问入口相关的常见页面或能力包括：

- **域名管理**
- **证书管理**
- **反向代理**

如果你的应用已经部署成功，但浏览器无法访问，或者 HTTPS、路径转发、域名解析存在问题，通常就应该优先回到这些入口处理。

## 进入域名管理

域名通常是从应用详情页进入管理的。

常见步骤：

1. 进入 **应用管理**。
2. 打开目标应用详情。
3. 点击 **域名管理**。

域名管理更适合处理某个应用自己的访问入口；如果问题已经超出单个应用，比如涉及统一证书或转发链路，通常还要进一步看 **证书管理** 或 **反向代理**。

## 添加域名

1. 进入 **应用管理**，打开目标应用。
2. 打开 **域名** 或 **域名管理**。
3. 点击添加域名，填写域名，并按页面要求选择要访问的服务和端口。
4. 保存后，按照解析提示到域名服务商处添加记录。
5. 等待解析生效，再用浏览器访问。

只填写域名时，使用 `www.example.com`，不要附加 `https://` 或 `/admin`。目标端口应按应用说明填写。

### 使用示例：绑定网站域名

假设应用已经运行，服务端口为 `8080`，面板提示入口地址为 `192.0.2.20`：

1. 在应用域名中填写 `www.example.com`，选择这个应用的服务及 `8080` 端口。
2. 到域名服务商的解析页面，添加一条 **A** 记录：主机记录填写 `www`，记录值填写 `192.0.2.20`。
3. 等待解析生效，用浏览器打开 `http://www.example.com`，应看到目标应用。
4. 确认访问正常后再配置 HTTPS。

这里的端口和地址都是示例。端口取应用提供的服务端口，解析地址取面板实际提示；若提示使用 CNAME，应按提示填写别名记录。

## HTTPS 配置

HTTPS 用于加密访问，网址以 `https://` 开头。

1. 先确认域名已经指向正确的服务器。
2. 在域名设置中开启 HTTPS。
3. 选择自动申请证书，或使用已有证书。
4. 等待证书就绪，再通过完整网址访问。显示“签发中”或“获取中”时还需要继续等待，保存成功不等于证书已经可用。

已有证书请打开 **https配置**，关闭 **自动https**，将 crt 证书文件和 key 私钥文件的内容分别填入文本框。证书必须与访问域名一致，并且没有过期。自动申请失败时，检查解析和服务器访问限制，再联系管理员。

## 证书管理什么时候会用到

如果你的关注点已经不只是“单个应用能不能开 HTTPS”，而是：

- 证书是否有效
- 证书是否即将过期
- 证书是否需要统一替换
- 不同应用的证书是否正常生效

这时通常就要进一步进入 **证书管理** 处理。

可以把它理解成：

- **域名管理** 更偏“给某个应用接入口”
- **证书管理** 更偏“处理 HTTPS 证书本身”

## 路径和转发规则

一个域名不一定只对应一个简单入口。很多应用会有：

- 主站和 API 分开
- 静态资源和动态请求分开
- 一个域名下挂多个路径

这时就需要通过路径和转发规则，把不同请求指向正确的目标服务。

### 常见适用场景

- 网站和 API 分开转发
- 一个域名下挂多个服务路径
- 某些静态资源路径需要单独处理

如果域名能打开，但页面内容不对或接口报错，通常要回头检查路径和转发规则。

## 反向代理什么时候会用到

如果你的目标已经不只是“给应用绑一个域名”，而是要处理更灵活的转发规则或统一访问入口，请直接查看：

- [反向代理](./reverse-proxy.md)

## 网关插件规则

域名策略中的 **更多** 用于配置网关插件规则。这里只显示已安装且勾选“支持规则配置”的插件；网关列表中的全局状态不会隐藏该入口，卸载插件后入口才会消失。

选择插件后，按照页面中的配置项填写并保存即可；官方应用提供的插件会在标题右侧显示 **官方** 标识。配置界面右上角可通过 **YAML 详情** 查看和编辑当前规则。没有关联到可用配置页面或操作界面加载失败时会直接进入同一个 YAML 只读预览，点击 **编辑** 后才能修改。插件的安装、全局配置和启停操作请前往 [网关插件](./gateway-plugins.md)。

域名的路径和转发设置与插件规则分别维护。删除域名或路径时，面板会清理对应插件关联，避免以后新建同名入口时意外沿用旧规则。

## 域名访问异常时先看什么

如果域名无法访问，建议先按这个顺序判断：

1. 域名是否已经正确解析
2. 应用本身是否已经正常运行
3. 访问入口或路径规则是否配置正确
4. HTTPS 证书是否已经生效
5. 是否需要进一步检查反向代理或集群内访问链路

很多“域名打不开”的问题，最后并不是域名本身的问题，而是应用状态、入口配置、证书状态或转发链路的问题。

### 常见现象与处理

| 现象 | 检查方法 |
| --- | --- |
| 域名打不开 | 核对解析地址、应用运行状态和访问端口 |
| 打开的是其他网站 | 核对实际域名是否绑定到了正确应用 |
| 提示连接不安全 | 核对证书域名、有效期和申请状态 |
| 首页正常，其他页面失败 | 检查路径和应用配置 |
| 刚修改解析仍看到旧结果 | 等待原记录的缓存时间结束，再重试 |

安装时使用的默认域名可能显示锁定图标，不能按普通域名直接删除。批量策略会把选定配置复制一次，之后单独修改一个路径不会自动持续同步到其他路径。

修改或删除线上域名前，确认是否还有用户或软件在使用这个地址。批量处理后刷新列表，核对每个目标的实际结果。

## 域名管理里最常见的误区

比较常见的误区包括：

- 以为应用运行了，域名就一定能访问
- 只配了域名，没有确认解析是否真正生效
- 开启了 HTTPS，但证书还没有生效
- 配了路径规则，但没有确认目标服务是否正确

域名管理的关键，不在于“配置动作做了没有”，而在于“从外部访问时整条链路是否真的通了”。

## 什么时候说明问题可能不只在域名页

如果你已经确认域名配置没明显问题，但访问还是异常，通常要进一步回到这些地方继续查：

- 应用运行状态
- 日志和事件
- 证书管理
- [反向代理](./reverse-proxy.md)
- 集群入口或服务转发状态
- [私有 DNS](./private-dns.md)

域名管理的价值，是把应用接到可访问状态；如果接不通，它也是定位访问链路问题的重要入口。
