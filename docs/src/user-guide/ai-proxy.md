# AI 代理

AI 代理基于 Higress，把不同厂商或自建的大模型 API 统一到一个访问域名，并支持多提供者权重分流、模型白名单和 Key Auth 认证。客户端通常只需要修改 API Base URL 和访问 Key，不需要感知后端提供者的地址和 Token。

## 适用场景

| 你想做什么 | AI 代理可以怎样帮助你 |
| --- | --- |
| 在多个 AI 软件中使用同一个服务 | 给这些软件填写统一的访问地址，由面板管理背后的模型服务 |
| 更换模型厂商 | 在面板中调整厂商设置；软件继续使用原来的地址，模型名称也要与新厂商支持的名称一致 |
| 给团队成员或不同软件分别使用 | 分别创建消费者密钥，需要时单独更换或撤销，不把厂商密钥直接交给每个人 |
| 只开放指定模型 | 在模型名称中填写允许使用的模型，避免使用其他模型 |
| 让多个服务共同处理请求 | 为支持相同模型的服务设置分配比例，也可停用其中一个，手动切换到备用服务 |
| 使用自己部署的模型服务 | 管理员可接入 Ollama、vLLM 等自建服务，使用者仍填写统一地址和密钥 |

如果只是转发普通网站，请使用 [反向代理](./reverse-proxy.md)。

## 使用前准备

- 一个可以修改解析记录的域名，例如 `ai.example.com`。
- 模型厂商提供的密钥，例如 DeepSeek 的 API Token。
- 可以管理 AI 代理的面板账号。

这里有两种密钥：**厂商密钥**用于面板连接模型厂商，**消费者密钥**用于你的 AI 软件连接面板。不要把厂商密钥直接发给其他使用者。

## 创建域名

1. 进入 **网关管理 → AI代理**。
2. 如果页面提示 AI 代理插件未安装，先点击 **安装 AI 代理插件** 完成制品安装。
3. 点击 **新增**，填写访问域名并按需启用 HTTPS 证书。
4. 创建完成后，在列表中点击 **编辑** 进入该域名的配置页。

域名必须先创建，模型、认证和服务提供者均在该域名的配置页维护。

## 配置路由

域名详情页上方的 **路由配置** 只作用于当前域名：

- **模型名称**：在域名路由配置中输入该域名支持的模型名称。配置后，请求体中的 `model` 必须在列表内，否则网关返回 HTTP 403；留空表示不限制模型。如果请求校验插件尚未安装，输入框保持禁用，可在该栏点击 **立即安装**。
- **认证**：启用后至少要创建一个消费者。消费者区域支持添加多个消费者，并展示消费者名称和认证方式。每个消费者可以配置多个认证令牌及独立的令牌来源。如果 Key Auth 认证插件尚未安装，开关保持禁用，可在该表单项点击 **立即安装**；无插件安装权限时请联系管理员。

点击 **添加消费者** 后会打开配置弹窗。消费者名称由系统自动生成且不能修改；认证方式使用 Tab 展示，当前只支持 **Key Auth**。Key Auth 支持添加多个认证令牌，每个令牌都可以手动填写或随机生成。令牌来源支持：

- **Authorization: Bearer ${value}**：通过标准 `Authorization` 请求头发送，适合 OpenAI SDK 等客户端；
- **自定义 HTTP Header**：需要同时填写 Header 名称，例如 `x-api-key`；
- **查询参数**：需要同时填写参数名称，例如 `apikey`，只建议临时调试使用。

点击弹窗确认后配置立即保存，不需要再次点击页面底部的 **保存配置**。编辑消费者时可以增加、删除或轮换认证令牌，也可以修改令牌来源及对应名称。

删除消费者会撤销对应的使用密钥和当前域名的授权。删除最后一个消费者时，该域名的认证会自动关闭。

## 配置服务提供者

一个域名可以创建多个 AI 服务提供者。创建和编辑表单会按照 Higress 的供应商能力显示专属配置，而不是使用统一的服务地址。服务提供者不单独限制客户端可请求的模型；模型白名单仍在域名路由配置中统一维护。

常用供应商包括 OpenAI/OpenAI 兼容服务、通义千问、DeepSeek、Azure OpenAI、Claude、智谱 AI、豆包、Gemini、Ollama、vLLM、AWS Bedrock 和 Google Vertex。不同类型会显示不同的专属字段。

- 只有启用的提供者会参与请求转发。
- 启用两个或更多提供者时，每个权重必须大于 0，且权重总和必须等于 100。
- 提供者名称只要求在当前域名内唯一；不同域名可使用相同显示名称，不同域名的设置分别保存。

供应商专属配置包括：

- **OpenAI**：官方服务或自定义兼容服务；自定义 URL 支持多个同协议、同路径的静态 IP 地址；
- **通义千问**：联网搜索、OpenAI 兼容模式、文件 ID、官方/自定义域名和推理内容处理模式；
- **Azure OpenAI**：填写包含 `api-version` 的完整服务 URL；
- **Claude**：Anthropic 官方服务或自定义服务 URL，并支持 API 版本和 Claude Code 模式；
- **Ollama / vLLM**：填写主机端口或一个、多个 vLLM 服务 URL；
- **AWS Bedrock / Google Vertex**：从 Higress 区域候选中选择或搜索区域；Vertex 还支持认证 JSON、令牌刷新提前量和 Gemini 安全设置。

所有供应商都可以设置流式首包超时。启用 **Token 故障转移** 后，还需设置连续失败/成功阈值、健康检查间隔、超时和健康检查模型；模型下拉优先显示当前供应商的 Higress 预置选项，也可以输入自定义模型名。

如果管理员已经配置网络代理，表单会显示 **代理服务器** 选项。需要中转访问厂商时选择对应代理；留空表示直接访问上游。没有候选项时，请管理员先配置。

选择协议时：

- **OpenAI/v1**：让客户端按 OpenAI API 格式请求，适合大部分统一接入场景；
- **原始协议**：保留对应厂商的原始请求协议，仅在客户端明确使用该厂商格式时选择。

## 完整配置示例：接入 DeepSeek

假设你已有 DeepSeek 的厂商密钥，希望通过 `ai.example.com` 在 AI 软件中使用它：

1. 按前面的步骤创建域名，并完成域名解析。
2. 添加服务提供者：供应商选择 **DeepSeek**，名称填写“常用模型”，协议选择 **OpenAI/v1**，填写厂商密钥，服务地址使用页面默认值，权重填写 **100**，开启启用。
3. 在模型名称中添加 `deepseek-chat`，开启认证，添加一个消费者，使用默认的 Bearer 方式并保存密钥。
4. 点击 **保存配置**。
5. 在支持自定义模型地址的软件中填写：

| 设置项 | 填写内容 |
| --- | --- |
| 服务地址 / Base URL | `https://ai.example.com/v1`，是否包含 `/v1` 以软件要求为准 |
| API Key | 刚创建的消费者密钥，不能填 DeepSeek 的厂商密钥 |
| 模型名称 | `deepseek-chat` |

发送“请用三句话介绍你能做什么”，确认能正常收到回复。配置中的示例域名需要替换成你自己的域名。

## 软件接入与密钥分配

| 软件中的设置项 | 示例 |
| --- | --- |
| 服务地址 / Base URL | `https://ai.example.com/v1` |
| API Key | 上一步生成的消费者密钥 |
| 模型 | `deepseek-chat` |

不同软件对地址是否包含 `/v1` 的要求可能不同，按该软件的说明填写。发送一句“你好”验证能否回复。

### 给不同软件分配独立密钥

假设你在电脑和手机上各使用一款 AI 软件：

1. 在同一个 AI 代理域名下添加两个消费者，分别保存各自的密钥，并记录哪个密钥用于哪款软件。
2. 两款软件填写相同的服务地址和模型名称，但使用不同的消费者密钥。
3. 停用其中一款软件时，删除它对应的消费者；另一款软件继续使用自己的密钥。

消费者用于分别管理访问密钥，不代表已经设置独立余额、用量上限或计费规则。删除最后一个消费者会关闭该域名的认证，操作后要检查认证状态。

AI 代理也可以供你自己的程序使用。以下示例沿用前面的 DeepSeek 配置：地址为 `https://ai.example.com/v1`，模型为 `deepseek-chat`，密钥为面板生成的**消费者密钥**。这些是使用已配置好的 AI 代理，不需要修改面板源码。

### curl 对话请求

curl 是在终端发送请求的工具。把下面的域名和密钥换成自己的值，再执行命令；成功时会返回包含模型回复的内容。

```bash
export AI_BASE_URL='https://ai.example.com/v1'
export AI_API_KEY='替换为消费者Key'

curl "$AI_BASE_URL/chat/completions" \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $AI_API_KEY" \
  -d '{
    "model": "deepseek-chat",
    "messages": [
      {"role": "system", "content": "你是一个简洁的中文助手。"},
      {"role": "user", "content": "用一句话解释 Kubernetes。"}
    ]
  }'
```

上面的例子使用消费者默认的 Bearer 认证方式。如果选择了自定义请求头，就应把认证行改成对应的请求头和密钥，例如 `-H "x-api-key: $AI_API_KEY"`。如果选择了查询参数，则按消费者设置的参数名传递密钥；不要把带密钥的完整地址分享出去。

### 流式响应

流式响应就是边生成边显示回复。先设置上一例中的 `AI_BASE_URL` 和 `AI_API_KEY`，再执行：

```bash
curl -N "$AI_BASE_URL/chat/completions" \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $AI_API_KEY" \
  -d '{
    "model": "deepseek-chat",
    "stream": true,
    "messages": [{"role": "user", "content": "写一首四行短诗"}]
  }'
```

### OpenAI Python SDK

SDK 是供程序调用服务的工具包。这里使用 OpenAI 的 Python 工具包连接你的 AI 代理地址，模型仍是上面配置的 `deepseek-chat`。运行前需要在 Python 环境中安装 `openai` 包。

消费者使用默认的 Bearer 认证方式时，可直接运行下面的代码。把地址和 `consumer_key` 换成自己的值；成功时会打印模型回复：

```python
from openai import OpenAI

consumer_key = "替换为消费者Key"
client = OpenAI(
    api_key=consumer_key,
    base_url="https://ai.example.com/v1",
)

response = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": "你好，请介绍一下自己"}],
)
print(response.choices[0].message.content)
```

### OpenAI Node.js SDK

Node.js 程序也可以使用同样的代理地址。项目中需要安装 `openai` 包，并将下面的代码保存为 `.mjs` 文件，或在已启用 ES 模块的项目中运行。

先设置消费者密钥（此处为终端命令，不是 JavaScript）：

```bash
export AI_API_KEY='替换为消费者Key'
```

再运行下面的代码，地址替换为自己的域名。成功时会打印模型回复：

```javascript
import OpenAI from 'openai';

const consumerKey = process.env.AI_API_KEY;
const client = new OpenAI({
  apiKey: consumerKey,
  baseURL: 'https://ai.example.com/v1',
});

const response = await client.chat.completions.create({
  model: 'deepseek-chat',
  messages: [{ role: 'user', content: '你好，请介绍一下自己' }],
});
console.log(response.choices[0].message.content);
```

## 多提供者权重示例

如果两个服务都支持相同的模型名称和请求方式，可以同时启用，并把权重分别设为 **70** 和 **30**。这表示访问量大致按这个比例分配，不是每十次请求一定有七次和三次，也不是“主服务失败才使用备用服务”。

如果只想保留备用服务，平时将它停用。需要切换时，在面板中停用原服务、启用备用服务，单个启用项可设置权重 **100**。切换后重新发送一条消息，确认备用服务可用；若模型名称不同，还需同步修改面板中的允许模型和软件中的模型名称。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 提示认证失败 | 核对是否使用消费者密钥，填写方式是否和消费者设置一致 |
| 提示模型不允许使用 | 核对软件中的模型名称与面板中的名称，包括大小写 |
| 连接失败或长时间无回复 | 检查域名、厂商地址和厂商账号余额，再查看页面错误 |
| 部分请求成功、部分失败 | 检查所有启用的厂商是否支持同一个模型 |
| 多个厂商保存失败 | 检查启用项的权重总和是否为 100 |

## 安全建议

- 不要把上游 Token 当作消费者 Key 分发；
- 不要把 Key 写入代码仓库、截图、URL 或日志；
- 为不同客户端创建不同消费者，便于单独轮换和撤销；
- 定期轮换消费者 Key 和上游 Token；
- 生产环境建议启用认证和 HTTPS；
- 删除消费者或域名前，先确认使用该 Key 的客户端已经迁移。

## 删除域名

不同软件建议使用不同消费者，方便单独更换或撤销密钥。删除最后一个消费者时，当前域名的认证会自动关闭，请及时检查认证状态，避免意外开放访问。

删除域名会同时清理它关联的厂商、消费者和访问规则，使用该地址的软件会停止工作。等待删除任务完成；如果失败，查看提示并点击 **重试未完成任务**。
