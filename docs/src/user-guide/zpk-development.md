# 制品工具使用说明

ZPK 工具在页面中叫 **制品开发**，用于管理应用安装包、版本和发布信息。“制品”可以理解为一份整理好的应用安装包，其他人可以通过面板安装和使用它。

本页介绍日常的页面操作。如果你只想安装别人提供的应用，直接阅读 [应用管理](./app-management.md)，不需要先学习制作安装包。

制作程序、填写复杂的运行配置和处理安装包格式，需要应用提供者协助，详细说明见 [制品开发指南](../development/zpk/index.md)。

## 这个工具能做什么

- 查看和整理自己的应用安装包。
- 修改应用名称、图标、介绍等展示信息。
- 上传应用提供者准备好的文件。
- 查看不同版本的说明和发布结果。
- 按需填写发布资料，提交应用发布。

这个工具需要另行安装。不同安装版本、账号权限下，菜单和按钮可能不同，具体以页面显示为准。

## 一、从哪里进入

1. 在面板 **应用管理** 中找到已安装的 **制品开发** 应用。
2. 打开它的管理页面，进入 **制品列表**。
3. 找到要维护的应用，点击进入详情。
4. 在详情中选择版本，再进行查看或修改。

如果没有找到应用或按钮，请管理员确认是否已安装，以及当前账号是否有操作权限。

### 页面上的名称怎么理解

| 页面名称 | 用来做什么 |
| --- | --- |
| 制品列表 | 查找要管理的应用安装包 |
| 版本管理 | 查看版本、更新说明和发布结果 |
| 应用介绍 | 编写别人安装前看到的说明 |
| 发布设置 | 查看命令行上传说明；网页发布按下文“发布到市场”操作 |
| 付费设置 | 需要收费时，按页面提示填写价格等信息 |

## 二、添加应用和填写基础信息

已经有安装包时，直接打开已有条目；需要新增时，再点击 **添加制品**。

1. 按弹窗要求填写标识。标识是应用在系统中的固定名称，用来区分不同应用。
2. 页面将标识分为两栏，两栏都只填写字母和数字，例如 `acme` 和 `blog`，组合后是 `acme-blog`。请换成自己的名称。
3. 创建完成后，打开已有的初始版本 **1.0.0**，不需要再创建同名版本。
4. 补充应用名称、图标、介绍和分类等页面要求的信息。
5. 保存后，回到详情检查显示内容是否正确。

![添加制品](/examples/zpk/01-add-product.png)

### 常见字段怎么填写

| 字段 | 填写建议 |
| --- | --- |
| 标识 | 使用自己的固定名称，创建后不要随意更换 |
| 名称 | 填写容易识别的应用名称，例如“公司网站” |
| 图标 | 选择能代表应用的图片 |
| 介绍 | 说明应用用途、安装要求和使用方法 |
| 分类 | 按实际用途选择，方便别人查找 |
| 版本说明 | 写清这一版新增、修复或调整了什么 |

名称、介绍等基础资料可能供多个版本共用。修改前先确认，不要把只属于某一次更新的内容全部写进应用名称或介绍里。

## 三、上传应用文件

应用提供者可能会给你一个或多个压缩包，并说明应该上传到哪个位置。请按说明选择对应版本和上传入口，不要只凭文件名猜测。

1. 打开需要修改的版本。
2. 进入应用提供者指定的文件上传页面。
3. 选择准备好的文件，等待上传完成。
4. 核对文件名称、内容和所属版本。
5. 按页面提示保存，再继续检查其他设置。

上传文件、保存设置和发布是不同步骤。上传完成后，还需要检查最终发布结果。

如果页面要求填写程序地址、端口或运行命令，请向应用提供者取得准确内容。不要为了通过表单而随意填写，也不要把源码包、网页包和安装包互相替代。

## 四、查看和维护版本

进入 **版本管理**，可以查看版本号、更新说明和发布状态。

![版本管理](/examples/zpk/02-version-management.png)

### 创建新版本

1. 确认要更新的应用。
2. 新增版本，填写三段数字，例如从 `1.0.0` 更新为 `1.0.1`。
3. 填写本次更新说明，例如“修复登录后页面打不开的问题”。
4. 创建后，检查文件和设置是否完整，再上传需要更换的内容。

当前网页不要在版本号前加 `v`，也不要填写 `1.0.1-beta` 这样的后缀。新版本创建成功后仍应核对内容，不能只看版本号就认为文件已经准备齐全。

## 五、提交后怎样确认成功

1. 检查应用名称、版本、文件和更新说明。
2. 在编辑页面点击 **确定提交**。正常完成编辑的流程会保存内容并发起发布。
3. 返回版本管理，刷新查看发布状态。
4. 显示发布失败时，先查看失败提示，核对已保存的内容，处理后再重试。

| 状态 | 接下来怎么做 |
| --- | --- |
| 未发布 | 继续检查文件和设置，完成提交 |
| 处理中 | 等待一段时间，再刷新查看结果 |
| 已发布 | 在测试环境安装，确认实际可用 |
| 发布失败 | 查看原因；无法处理时联系应用提供者或管理员 |

只看到“修改成功”或页面跳转，还不能说明发布已经完成。发布后也应实际安装并打开应用，检查主要功能是否正常。

### 示例：更新一份已有的应用安装包

假设应用当前版本是 `1.0.0`，应用提供者给了你修复后的文件：

1. 打开该应用，新建 `1.0.1` 版本。
2. 更新说明填写本次修复内容。
3. 按提供者说明上传新文件，核对没有选错版本。
4. 检查设置并提交，刷新直到看到 **已发布**。
5. 先在测试环境安装或更新，检查登录、页面和主要操作。
6. 确认正常后，再安排正式使用的应用更新；更新前备份重要数据。

发布新安装包不会替你确认所有已安装应用都已更新。正式应用的更新结果，需要到 [应用管理](./app-management.md) 中另行检查。

## 六、发布到市场和付费设置

发布到市场后，其他人才能按市场的展示与购买规则找到你的应用。完整流程是：**确认账号 → 补齐资料 → 设置费用 → 开启市场发布 → 发布版本 → 查看审核结果 → 检查市场展示**。

### 第一步：确认绑定的是正确的云端账号

1. 回到面板，打开 **系统管理 → 云端账号**。
2. 尚未绑定时，点击 **登录云端**，按页面提示登录并完成绑定。
3. 已绑定时，检查页面显示的账号是否正确。
4. 返回制品工具，打开要发布的应用。

发布使用的是面板绑定的微擎云端账号。已有应用必须使用与该应用所属账号一致的账号；出现“账号不一致”提示时，请负责人确认正确账号，再切换后重试。

### 第二步：补齐应用资料

在该应用的 **版本管理** 页，找到 **基础信息**，点击 **编辑**：

| 内容 | 怎么填写 |
| --- | --- |
| 图标 | 上传能代表应用的图片，检查预览是否正常 |
| 名称 | 填写对外展示的名称，例如“企业预约助手” |
| 描述 | 简要说明用途，例如“支持在线预约、订单查询和通知提醒” |
| 分类 | 选择与用途相符的分类；没有分类会无法提交市场 |
| 应用介绍 | 说明主要功能、适用人群、安装要求和使用注意事项 |

保存后重新查看，确认名称、图片和文字都正确。分类已经由应用类型固定时，按页面显示保留。

需要补充操作手册时，可进入 **应用文档**，添加或修改文档并点击 **保存**。不要把填写文档当作已经完成市场发布，最终展示内容仍需到市场详情核对。

### 第三步：核对免费、收费和试用设置

打开 **付费设置**，根据实际销售方式填写：

- **授权费用**：用户获得应用商业使用权的费用。免费提供时填写 `0`，收费时填写实际金额。
- **免费试用**：需要试用时开启，并填写试用天数；不提供则关闭。
- **升级服务费用**：需要对后续升级收费时再配置，不清楚规则时请负责人确认。
- **周期服务费用**：按服务期限收费时开启，检查套餐价格、时长以及是否勾选生效。

填写后点击页面底部的 **确定**。回到该页核对费用没有填错，特别注意金额、赠送项目和生效开关。已提供给用户的试用时长，不会随之后修改的设置一起改变。

### 第四步：开启“自动发布到制品市场”

1. 返回 **版本管理**。
2. 在 **开发版本** 标题旁勾选 **自动发布到制品市场**。
3. 等待保存完成，再检查勾选状态是否保留。

这个选项决定后续发布是否同时提交到市场。**只勾选开关不会立即发布已有版本**，还需要执行下一步。

页面中的 **发布设置** 页签目前主要展示命令行上传说明，普通用户通过网页发布时，不需要照着执行里面的命令。

### 第五步：发布目标版本

1. 找到准备发布的版本，核对版本号和版本说明。
2. 确认应用提供者已准备好文件，并已在测试环境验证主要功能。
3. 对页面上可发布的版本点击 **点击发布**。如果正在编辑应用，也可以在正常完成编辑后点击 **确定提交**，由该流程发起发布。
4. 等待处理，返回版本管理并刷新，检查版本发布结果和市场审核状态。

如果版本已经显示“已发布”，但当时没有开启市场发布，不要认为刚勾选开关就会自动补交市场。请应用维护人员按当前版本提供的编辑或发布入口重新发起发布；没有可用入口时，先确认处理方式，不要为了重试随意下架或新建版本。

遇到错误时先记下完整提示，核对资料和已有结果后再操作。应用安装包发布与市场提交可能只有一部分完成，不能只凭“操作成功”判断全部完成。

### 第六步：查看审核结果

在 **当前线上版本** 区域查看带云朵图标的市场状态。该状态入口可以打开关联的市场详情页。

| 审核状态 | 含义与处理方法 |
| --- | --- |
| 待审核 | 已提交，等待市场审核；可打开详情查看，暂时不要反复提交 |
| 审核失败 | 打开市场详情查看是否有具体原因，按要求修正；不清楚时联系市场管理人员 |
| 审核通过 | 审核已通过，继续检查市场中的实际展示和安装入口 |
| 没有市场状态 | 尚不能确认提交成功，核对市场发布开关、发布提示和账号，再刷新查看 |

以线上版本区域和市场详情的审核结果为准。开发版本旁的单个标签不能代替完整审核结果；页面没有自动更新时，请手动刷新。

审核失败后，先分清是展示资料需要修改，还是应用文件有问题。资料问题按市场要求修改并重新提交；涉及文件或功能修复时，请应用提供者准备修复版本，再按前面的流程发布。

### 第七步：检查市场中的实际结果

审核通过后，打开市场详情逐项检查：

1. 应用名称、图标、描述和分类是否正确。
2. 价格、试用和服务期限是否符合预期。
3. 用户能否找到预期的购买或安装入口。
4. 实际安装到的版本是否正确，主要功能是否可用。

若审核通过但仍无法找到或安装，记录应用名称、版本和市场页面提示，联系市场管理人员确认展示及销售状态。

### 示例：首次发布一个免费应用

以“企业预约助手” `1.0.0` 为例：

1. 确认面板已绑定该应用所属的云端账号。
2. 在 **基础信息 → 编辑** 中填写名称、上传图标、补充描述并选择分类，保存。
3. 在 **付费设置** 中将授权费用设为 `0`；本例不设置升级收费和周期收费，检查相关选项后点击 **确定**。
4. 返回 **版本管理**，勾选 **自动发布到制品市场**，等待保存。
5. 找到 `1.0.0`，点击可用的 **点击发布**，检查发布结果。
6. 看到 **待审核** 后等待审核；通过后打开市场详情，核对免费设置和安装入口。
7. 实际安装一次，确认进入应用后主要功能正常。

以上名称只是示例，请替换成自己的应用。免费应用也需要核对资料、审核和安装结果。

## 七、遇到问题先看哪里

| 问题 | 检查方法 |
| --- | --- |
| 标识不能保存 | 检查两栏是否只用了字母和数字，以及是否与已有名称重复 |
| 找不到刚创建的版本 | 刷新列表，确认当前打开的是正确应用 |
| 文件上传了，但内容不对 | 核对上传入口、文件和版本，联系文件提供者确认 |
| 一直显示处理中 | 刷新检查；长时间不变时，把应用名称、版本和提示交给管理员 |
| 版本发布成功，市场找不到 | 检查是否提交市场，以及审核是否通过 |
| 应用安装后打不开 | 查看应用运行情况、日志和访问地址，见 [应用管理](./app-management.md) |

修改或重试前先检查已有结果，避免重复上传或覆盖其他版本。需要制作安装包、配置程序运行方式或使用命令行工具时，请阅读 [制品开发指南](../development/zpk/index.md)。
