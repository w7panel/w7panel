# 私有 DNS

私有 DNS 用于处理集群内部或私有环境中的域名解析问题。它适合解决“服务已经存在，但内部访问、解析或连接仍然不通”的场景。

## 进入私有 DNS

进入 **网关管理 → 私有DNS**。这里用于内部名称解析，不会自动修改域名服务商处的公网记录；使用方还需接入这套内部解析服务。

## 这个页面主要能做什么

根据当前前后端能力，私有 DNS 主要覆盖下面几类操作：

- **DNS Zone 管理**：查看 zone 列表、创建 zone、删除 zone
- **DNS 记录管理**：查看记录列表、创建记录、修改记录、删除记录
- **同步状态查看**：查看控制器同步状态和失败信息
- **解析诊断**：测试某个域名的 IP 解析结果或 CNAME 解析结果

可以把它理解成：这里管理内部域名记录；公网网站访问请另行配置域名解析和访问入口。

## 什么时候适合用私有 DNS

常见场景包括：

- 需要确认某个域名在当前环境里能不能被正确解析
- 需要为内部服务创建或维护私有解析记录
- 需要处理集群内服务访问
- 需要排查内部代理或连接诊断问题
- 应用已经启动，但内部访问链路仍然不通

如果你的问题不是公网访问，而是集群内服务之间互通、内部解析或私有网络下的访问问题，通常就应该优先看这里。

## DNS Zone 管理

DNS Zone（域名区域）就是某个域名下全部解析记录的集合。

### 常见操作

在私有 DNS 页面里，通常会先看到 zone 列表。围绕 zone，常见操作包括：

- 查看已有 zone
- 新建 zone
- 删除不再使用的 zone

### 新建 Zone

1. 进入 **网关管理 → 私有DNS**。
2. 点击新建或添加 zone。
3. 输入域名。
4. 确认创建。

创建时，域名本身需要是合法格式。一般来说，至少应是一个完整域名，而不是单个无后缀名称。

## DNS 记录管理

进入某个 zone 后，通常可以继续管理它下面的记录。

### 常见操作

- 查看记录列表
- 新建记录
- 修改记录
- 删除记录

### 常见记录类型

当前能力里可以确认的常见记录类型包括：

- `A`
- `AAAA`
- `CNAME`
- `TXT`
- `MX`

不同记录类型对应不同校验规则。例如：

- `A` 需要是 IPv4
- `AAAA` 需要是 IPv6
- `CNAME` 需要是合法域名
- `TXT` 不能包含换行

### 新建记录时通常要填什么

通常会涉及这些字段：

- 主机记录名
- 记录类型
- 记录值
- TTL
- MX 优先级（仅在需要时）

如果你不确定填什么，建议先明确你要解决的是“把域名指到某个 IP”，还是“把域名别名到另一个域名”。

### 记录类型与填写示例

| 类型 | 用途 | 记录值示例 |
| --- | --- | --- |
| A | 名称指向一个普通服务器地址 | `192.0.2.10`，请替换为实际地址 |
| AAAA | 名称指向一个 IPv6 地址 | 使用服务器实际的 IPv6 地址 |
| CNAME | 名称指向另一个域名 | `database.example.com` |
| TXT | 保存验证文字等信息 | 按需要填写验证方提供的文字 |
| MX | 指定邮件服务器 | 按邮件服务商要求填写 |
| NS | 指定负责某个域名的解析服务器 | 按管理员提供的名称填写 |

**主机记录**填写 `@` 表示当前域名本身，填写 `www` 表示它下面的 `www` 子域名。

**TTL** 表示解析结果可以被记住多长时间，单位为秒，页面默认 60 秒。修改记录后，已有解析结果可能要等这段时间过后才会更新。

## 同步状态

- **Ready**：设置已经同步。
- **Pending** 或尚无状态：正在等待处理。
- **Failed**：同步失败，查看页面提示；可把提示交给管理员。

## 解析诊断

保存记录后，在已接入内部解析服务的设备上检查结果。下面的配置示例提供 `nslookup` 验证命令。解析正确后，还需确认目标服务和端口可以连接；解析成功不代表服务已经启动。

### 使用示例：内部数据库名称

假设数据库服务器的内部地址是 `192.0.2.10`，希望使用 `db.example.com` 访问：

| 输入项 | 示例值 |
| --- | --- |
| 管理的域名 | `example.com` |
| 主机记录 | `db` |
| 类型 | `A` |
| 记录值 | `192.0.2.10`，替换为实际数据库地址 |
| TTL | `60` |

保存并等待 Ready。在已接入这套私有 DNS 的电脑或应用终端中，可以用下面的命令检查（需要安装 `nslookup` 工具）：

```sh
nslookup db.example.com
```

结果应包含你填写的数据库地址。如果仍查不到，请管理员确认当前设备使用的是这套内部解析服务。数据库连接中将主机改为 `db.example.com`，端口、账号和密码仍按数据库实际配置填写；解析成功不表示数据库端口已经允许连接。

## 遇到什么问题时优先检查这里

如果你看到下面这些情况，建议优先检查私有 DNS：

- 域名本身看起来正常，但内部访问不通
- 服务已经运行，但集群内服务之间无法互相访问
- 应用可以被外部打开，但内部依赖连接失败
- 某个内部域名解析结果不符合预期
- 反向代理、内部代理或转发链路表现异常

## 排查时先看什么

建议先按下面顺序判断：

1. 目标服务本身是否存在并正常运行
2. 当前问题发生在公网访问，还是集群内访问
3. 对应 zone 是否存在
4. 记录类型和值是否配置正确
5. zone 同步状态是否为 `Ready`
6. 实际查询到的地址或别名是否符合预期

如果你把公网入口问题和内部解析问题混在一起看，通常会很难定位真正原因。

## 使用私有 DNS 时的建议

- 先区分清楚问题发生在外部访问还是内部访问
- 内部访问问题优先看 zone、record 和同步状态
- 如果涉及代理或转发，要同时确认目标服务本身是否可用
- 排查时尽量把“解析问题”和“服务本身问题”分开判断

私有 DNS 的价值，是帮助你把“服务已经存在”推进到“服务在真实内部环境里可以被正确找到和访问”。
