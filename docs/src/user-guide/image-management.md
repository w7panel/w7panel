# 镜像管理

镜像管理更偏向节点侧运维，主要处理镜像准备、镜像导入整理和本地镜像相关问题。它适合排查“应用为什么拉不到镜像”或“节点上镜像是否已经准备好”这类问题。

在当前面板里，镜像相关能力不只有 **镜像管理** 列表页，还包含一个隐藏的 **构建镜像** 链路，用来处理更进一步的镜像构建场景。

## 进入镜像管理

1. 登录微擎面板。
2. 在左侧菜单进入 **集群管理**。
3. 点击 **镜像管理**。

如果你处理的是“节点上已有镜像怎么看、镜像是否准备好”，通常从 **镜像管理** 开始；如果你处理的是“镜像如何被构建出来”，则还需要进入后续的 **构建镜像** 相关页面或流程。

## 适合什么场景

常见场景包括：

- 查看节点侧已有镜像
- 确认镜像是否已经存在
- 排查镜像拉取相关问题
- 处理本地镜像导入、整理或提交
- 结合构建型应用或节点侧镜像准备做进一步维护

如果应用部署失败、镜像构建异常，或者你怀疑问题出在节点镜像侧，通常就应该优先进入镜像管理。

## 进入后先看什么

通常建议优先确认：

- 目标镜像是否已经存在
- 镜像标签是否正确
- 节点侧镜像是否处于可用状态
- 当前问题是“镜像不存在”还是“镜像有了但应用仍然异常”

列表中镜像 ID 作为辅助信息显示在镜像名称下方，用于区分同名标签对应的实际镜像内容。

## 本地镜像管理什么时候会用到

本地镜像管理更适合这些情况：

- 需要把镜像导入到当前集群环境
- 需要整理已有本地镜像
- 需要确认应用依赖的镜像是否已经就位
- 需要从运行中的容器进一步生成镜像或处理镜像结果

如果你的环境并不完全依赖外部镜像仓库，这部分能力会很实用。

## 构建镜像什么时候会用到

如果你的目标不是确认节点上“有没有镜像”，而是要把代码包、制品或构建结果进一步变成可用镜像，这时通常会进入 **构建镜像** 相关流程。

可以简单理解成：

- **镜像管理** 更偏查看、导入、整理和确认镜像状态
- **构建镜像** 更偏把内容实际构建成镜像结果

## 镜像相关问题怎么判断

如果应用部署异常，建议先从这几个方向判断：

1. 目标镜像名称和标签是否正确
2. 节点侧是否已经存在该镜像
3. 镜像准备是否正常完成
4. 问题在镜像侧，还是在应用启动后的其他环节

很多时候，应用异常的根因并不在配置本身，而是在镜像根本没有准备好。

## 使用镜像管理时的建议

- 先确认问题是不是镜像侧，再进入镜像管理
- 处理镜像前，先核对镜像名和标签
- 如果涉及导入、提交或整理，最好先明确目标用途
- 不要把应用启动问题和镜像准备问题混在一起判断

镜像管理的价值，是让你更快判断节点镜像侧是否已经准备就绪，并把镜像相关问题和应用层问题分开看清楚。
