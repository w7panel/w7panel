# FAQ

本文面向第一次接触微擎面板（W7Panel）的用户，重点回答三类最常见的问题：

- 这套面板适不适合我
- 安装或环境出问题时先查哪里
- 实际使用中遇到问题应该先看哪一类文档

如果你已经准备开始操作面板，建议把这篇 FAQ 当成“快速判断入口”，而不是详细操作手册。

## 一、入门理解

### 微擎面板一定要配合 Kubernetes 使用吗？

是的。W7Panel 的核心定位就是 Kubernetes 场景下的云原生应用管理平台。

如果你完全不使用 Kubernetes，那么 W7Panel 并不是为这类环境设计的。

### 我不会 `kubectl`，还能使用微擎面板吗？

可以。W7Panel 的一个重要目标，就是降低 Kubernetes 的使用门槛。

很多原本需要命令行完成的事情，都可以通过界面完成，例如：

- 创建和部署应用
- 查看运行状态、日志和事件
- 管理域名、证书和访问入口
- 浏览容器文件、上传下载和在线编辑
- 查看存储资源和卷使用情况

不过，如果你能理解一些基础概念，例如命名空间、Pod、Service、Ingress、存储卷，会更容易理解面板里的功能含义。

## 二、安装与环境

### 安装时自动识别的公网 IP 不对怎么办？

如果服务器通过 NAT 出网，安装过程中自动识别到的公网 IP 可能不正确，从而导致访问异常。

这种情况下，安装时应显式指定公网 IP：

```bash
PUBLIC_IP=123.123.123.123 sh install.sh
```

### IPv6 会影响安装或访问吗？

会。在某些环境里，如果公网 IP 或内网 IP 走 IPv6，可能导致网络组件安装异常或后续访问问题。

常见处理思路是：

- 优先使用 IPv4 安装
- 必要时显式指定 `PUBLIC_IP` 和 `INTERNAL_IP`

例如：

```bash
PUBLIC_IP=123.123.123.123 INTERNAL_IP=123.123.123.123 sh install.sh
```

### 多节点环境下，为什么 Agent 会突然连不上？

一个常见原因是 Server 节点 IP 变化后，Agent 节点仍然指向旧地址，导致通信失败。

如果你在多节点环境中遇到节点异常、部分功能失效或 Agent 不在线，建议优先检查：

- 节点 IP 是否变化
- `kubectl get node -o wide` 输出是否正常
- Agent 节点上的 `K3S_URL` 是否仍然指向旧地址

### 为什么安装后面板起不来，和 SELinux 或云厂商安全组件有关吗？

有可能，而且这是比较常见的环境问题。

例如：

- SELinux 可能拦截 `k3s` 或 `k3s-agent` 启动
- 阿里云安全加固或阿里云盾可能影响面板相关组件启动
- 腾讯云云镜可能额外占用较多资源，影响低配置服务器运行

### 非大陆地区服务器安装时长时间卡住怎么办？

常见原因通常是镜像拉取过慢或失败，而不是安装流程完全中断。

如果你在香港、新加坡、美国等地区部署时卡在等待阶段，可以优先检查：

- 镜像是否已经开始拉取
- `k3s` 是否正常运行
- Pod 是否在持续启动
- 镜像源配置是否需要调整

### 误删了微擎面板应用，还能恢复吗？

可以。误删 `w7panel-offline` 后，通常可以通过 Helm 重新安装对应 chart 来恢复访问。

### 忘记管理员密码怎么办？

可以在 master 节点通过命令重新注册管理员账号密码。

常见做法是执行类似下面的命令：

```bash
kubectl exec -it $(kubectl get pods -n default -l app=w7panel-offline | awk 'NR>1{print $1}') -- k8s-offline auth:register --username=admin --password=123456
```

## 三、使用与排查

### 文件管理管理的是哪类文件？

主要是容器或应用运行环境中的文件，不是传统桌面操作系统里的本地文件管理。

常见用途包括：

- 修改应用配置文件
- 上传静态资源、脚本或备份包
- 下载运行产物
- 在线排查容器目录结构
- 调整文件权限

### 域名和 HTTPS 是面板内置支持的吗？

是的。W7Panel 提供域名和证书相关能力，目的是让应用从“已经部署”进一步走到“能够被正常访问”。

### 应用创建后一直无法访问，我应该先查什么？

可以按下面顺序先做初步排查：

1. 确认应用本身是否已经正常运行
2. 查看应用事件和运行日志
3. 检查域名绑定和解析是否正确
4. 确认 HTTPS / 入口配置是否已生效

如果应用本身没启动成功，先看应用状态和日志；如果应用已运行但外部访问异常，再重点排查域名、入口和网络路径。
