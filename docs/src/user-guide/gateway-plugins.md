# 网关插件使用指南

网关插件可以为网站增加访问控制等能力。本指南说明插件的安装流程，并以域名白名单插件为例介绍如何使用。

插件制品统一在 **网关管理 → 网关插件** 中管理，不会出现在顶部菜单、应用直达或普通应用列表中。

## 开始前

操作前请确认：

- 已经登录面板；
- 账号可以访问制品市场和网关管理；
- 需要配置的网站已经添加到面板，并且域名可以正常访问。

## 安装插件

所有网关插件都从制品市场安装。进入 **网关管理 → 网关插件** 后，页面会直接展示制品市场中的网关插件，并按“认证鉴权、安全防护、流量管控、请求响应转换、可观测性、AI”等分类组织；没有插件的分类不会显示。

分类标题右侧会显示插件数量。点击分类标题可以收起或展开该分类；重新进入页面时所有分类默认展开。域名管理“更多”中的插件分类也采用相同操作。

1. 在面板左侧进入 **网关管理 → 网关插件**。
2. 在对应分类中查找插件，也可以使用右上角搜索框。
3. 未安装插件的状态显示为 **待安装**，点击右侧 **安装**。
4. 按照制品安装页面的提示完成安装。
5. 返回网关插件列表；如果需要全局生效，确认 **全局状态** 已开启。

如果列表中没有看到插件，先确认安装任务是否成功，再刷新页面。

通过官方制品安装的应用，其网关插件标题右侧会显示 **官方** 标识，并且不能在网关插件列表中编辑插件信息。是否允许卸载由插件所属应用的删除保护设置独立决定；受保护的应用不显示卸载入口，未设置删除保护时可以卸载。执行卸载会卸载插件所属的完整应用，并清理该应用包含的全部网关插件及关联资源，而不是只删除当前插件。全局状态和域名规则配置不受影响。

插件所属应用制品有新版本时，标题右侧会显示 **新版本**。点击后可以查看更新说明或选择 **立即更新**；更新会升级插件所属的整个应用制品，同一制品中的配置界面和相关资源会一起更新。

## 配置域名白名单

假设网站使用下面两个域名：

- `example.com`
- `api.example.com`

希望只允许这两个域名通过网关访问。

### 第一步：安装域名白名单插件

1. 进入 **网关管理 → 网关插件**。
2. 在“安全防护”分类中找到“域名白名单”，也可以搜索插件名称。
3. 点击 **安装** 并完成制品安装。
4. 安装完成后返回网关插件列表。

### 第二步：添加允许访问的域名

1. 找到“域名白名单”插件。
2. 点击 **全局配置**。
3. 进入 **白名单配置**。
4. 点击 **添加**。
5. 输入 `example.com`，打开这一行的开关。
6. 再添加一行，输入 `api.example.com`，同样打开开关。
7. 点击 **保存**。

填写域名时只填写域名本身。例如填写 `example.com`，不要填写：

```text
https://example.com
example.com:443
example.com/admin
```

### 第三步：设置拦截提示

在同一个配置页面进入 **错误页配置**，可以设置其他域名被拒绝时看到的内容。

例如：

| 配置项 | 填写内容 |
|--------|----------|
| 错误码 | `404` |
| 内容 | `not found` |

填写后点击 **保存**。

### 第四步：确认是否生效

1. 访问 `https://example.com`，网站应正常打开。
2. 访问 `https://api.example.com`，接口应正常响应。
3. 使用一个没有加入白名单的域名访问网关，应看到 HTTP 404 和 `not found`。

如果允许的域名也被拒绝，请检查域名是否拼写正确、该行开关是否开启，以及插件的全局状态是否已开启。

## 开启或关闭全局配置

进入 **网关管理 → 网关插件**：

- 列表提示中的 **全局状态** 只控制插件的全局配置，不影响任何域名规则；
- 关闭 **全局状态**，只停止 `defaultConfig` 对全局流量生效，已经填写的全局配置会保留；
- 打开 **全局状态**，恢复全局配置；
- 域名规则使用各自的规则开关，不受列表中的全局状态影响。

配置页面可能会根据另一作用域的配置显示提示或可选项。例如规则配置页面可以读取当前插件的全局配置，插件全局配置页面也可以读取已有域名规则摘要。这些信息仅用于判断和展示，不会改变当前保存范围；全局入口只保存全局配置，域名“更多”入口只保存当前域名规则。

从 Higress Console 或 YAML 导入的插件如果省略 Disable 字段，面板会按照 Higress 语义将其识别为已启用。已有规则使用域名或后端服务作为匹配范围时，面板也可以识别；编辑覆盖多个目标的共享规则时，会保留其他目标的原配置。

## 查看和编辑 YAML

插件全局配置和域名规则配置都提供统一的 YAML 配置：

- 插件带有操作界面时，点击右上角 **YAML 详情** 查看当前配置；预览默认只读，点击 **编辑** 后可以直接修改并保存，点击 **取消** 返回操作界面。
- 插件没有关联到可用配置页面，或操作界面加载失败时，会直接打开同一个 YAML 只读预览，点击 **编辑** 后才能修改。
- YAML 只表示当前全局或域名规则的配置对象，不会修改其他作用域配置。
- YAML 模式不提供开启或关闭操作，保存 YAML 会保持插件或规则原有状态；全局状态在插件列表修改，规则状态在域名“更多”列表修改。

如果错误配置导致网站无法访问，全局配置应关闭列表中的 **全局状态**；域名规则应在该域名的“更多”中关闭对应规则。两种开关互不影响。

## 常见问题

### 安装后找不到插件

返回制品安装页面确认安装是否成功，然后刷新 **网关管理 → 网关插件**。

### 找不到“全局配置”按钮

该插件可能只支持针对单个域名配置。进入应用的 **域名管理 → 域名策略 → 更多** 查找插件。

### 域名策略中找不到插件

确认插件已经安装。如果仍未显示，说明该插件不支持针对单个域名配置；全局状态关闭不会隐藏规则配置入口。“更多”列表中的规则状态只控制当前域名，不影响插件的全局配置或其他域名。

编辑插件并取消 **支持规则配置** 时，系统会提示该插件将从域名“更多”中隐藏，并停用全部已有规则。重新勾选支持规则配置不会自动恢复这些规则，需要在对应域名中重新开启。

### 保存后没有生效

依次检查：

1. 使用全局配置时，全局状态是否已开启；
2. 使用规则配置时，当前域名的规则是否已开启；
3. 配置的域名是否与实际访问域名一致；
4. 浏览器或接口请求是否经过当前网关。

删除域名或路径时，面板会同步清理 WasmPlugin 中对应的 Ingress 引用，避免以后创建同名路由时恢复旧插件配置。
