# 镜像仓库缓存

镜像是启动应用的程序包。本应用将下载过的镜像保存起来，减少重复向外部仓库下载。它需要另行安装，页面及可用选项以已安装版本为准。

这里要区分三个地址：**缓存入口**是服务器下载时访问的域名；**缓存镜像仓库**保存下载内容；**镜像仓库源或源站**提供原始镜像。

## 这个应用能做什么

- 按域名建立镜像下载入口。
- 设置缓存保存位置及原始镜像来源。
- 按镜像名称决定是否缓存、缓存多久。
- 为镜像源填写账号或网络代理。
- 查看尚未完成或失败的同步任务。
- 在公开首页生成服务器接入所需的镜像配置。

只保存设置不会自动修改所有服务器的下载入口，使用方还需要完成接入。

## 主要页面怎么理解

| 页面 | 用途 |
| --- | --- |
| 站点列表 | 添加入口域名、修改设置、查看同步状态、配置 HTTPS 或删除站点 |
| 站点详情 | 分为“缓存镜像配置”和“缓存镜像仓库配置” |
| 全局缓存仓库配置 | 为多个站点准备共用的保存位置和账号 |
| 公开首页 | 展示加速入口，使用镜像配置生成器 |
| 页面设置 | 管理公开首页的说明和备案、版权信息 |

从面板打开应用进入管理页面；独立打开应用根地址时，可能先看到公开首页。

## 一、从哪里开始最合适

1. 安装并打开镜像仓库缓存应用。
2. 请管理员准备一个可保存镜像的仓库，并配置全局缓存仓库。
3. 在列表点击 **添加站点**，填写自己的缓存入口域名，按提示完成解析。
4. 点击该站点的 **修改**，确认缓存镜像仓库，再设置镜像来源与规则。
5. 点击页面的保存按钮，重新进入核对内容。
6. 在一台测试服务器配置下载入口，下载一个镜像并检查同步状态。

不要把保存缓存的仓库地址和对外访问的缓存入口混为一处。

## 二、缓存仓库列表页可以做什么

当前列表按 **域名** 展示站点，提供 **添加站点**、**修改**、**查看同步状态**、**https配置** 和 **删除**。

添加站点后还需完成保存仓库、源站和规则配置。开启自动 HTTPS 时，等待解析和证书就绪，再让客户端使用安全地址。

删除前先让使用方切换到其他可用入口。删除站点配置和访问入口不等于已经删除保存仓库中的全部镜像，不要把它当作清理磁盘空间的方法。

## 三、设置页里最重要的几块配置

| 页签或区域 | 要解决的问题 |
| --- | --- |
| 缓存镜像仓库配置 | 下载的内容保存到哪里，账号是否有权限 |
| 缓存镜像配置 → 镜像仓库源配置 | 可以从哪些仓库下载原始镜像 |
| 缓存镜像配置 → 源站信息配置 | 当前入口对应的原始仓库地址 |
| 缓存镜像配置 → 镜像缓存配置 | 哪些镜像缓存、保留多久及匹配顺序 |

至少填写一个镜像仓库源或源站地址，否则页面不能保存。公开首页生成客户端配置时，还需要当前站点标明适用的源站地址。

## 四、缓存仓库怎么理解

进入 **缓存镜像仓库配置**，选择 **全局配置** 或 **自定义**：

| 字段 | 填写说明 |
| --- | --- |
| 镜像仓库地址 | 保存缓存的仓库；先选择 http 或 https，再填地址 |
| 存储目录 | 在该仓库中的目录，例如 `/cache`；未填写时用 `/` |
| 用户名、密码 | 保存仓库的访问账号，不能用源仓库账号随意替代 |

全局模式继承仓库地址和账号，当前站点仍可设置自己的存储目录；自定义模式为当前站点单独填写资料。

保存缓存需要仓库写入权限；使用方下载权限也受保存仓库的权限设置影响。仓库设为私有时，应由管理员确认客户端登录与读取权限，不能认为配置了后台账号就自动对所有人开放。

修改全局配置会影响继承它的站点，先确认使用范围。

## 五、源仓库和认证怎么理解

**镜像仓库源配置**可以添加多个来源；**源站信息配置**单独填写当前入口对应的原始仓库，例如协议 `https://`，地址 `registry-1.docker.io`。

1. 在镜像源表格点击 **新增**，填写协议、地址和权重。
2. 需要登录或网络代理时，点击该行 **设置**。
3. 在 **访问代理** 填写中转地址和端口；在 **镜像仓库权限** 填写源仓库用户名、密码。
4. 弹窗点 **确定** 后，还要保存整个站点配置。

弹窗中的用户名、密码是镜像仓库权限，不是另一个代理账号输入项。使用公共源时，是否需要账号按源仓库要求判断。

### 多个来源怎么选择

页面提示权重从小到大，但当前下载会同时向候选来源查找可用内容，不能将权重理解为“主源失败才请求备用源”。单独填写的源站也可能参与查找。

规则中选择 **指定镜像仓库源** 后，仅使用指定来源，不会自动再尝试其他来源。来源故障时需要检查该项。

### 下载失败先检查什么

核对镜像名称、版本、源仓库权限及网络代理；缓存入口、保存仓库和原始来源之间都需要能正常连接。

## 六、镜像缓存规则怎么理解

在 **缓存镜像配置** 的规则表中点击 **新增**：

| 字段 | 含义 |
| --- | --- |
| 是否缓存 | 打开才保存匹配内容；新增规则默认关闭，需手动开启 |
| 缓存时间(分钟) | 正数表示更新间隔，`0` 表示不自动过期，不是禁用缓存 |
| 镜像地址匹配 | 选择全部、精准匹配、前缀匹配或正则匹配 |
| 指定镜像仓库源 | 只使用选定来源，不选择时使用候选来源 |
| 权重 | 普通匹配规则数值越小越先检查，不是流量百分比 |
| 分布下载 | 调整下载方式，初次使用可保留关闭 |

匹配的是镜像名称，例如 `library/nginx`，不带 `https://`、缓存域名或 `:1.28` 标签。

| 匹配方式 | 填写示例 |
| --- | --- |
| 精准匹配 | `library/nginx`，仅这个镜像名称 |
| 前缀匹配 | `library/`，匹配该目录下的名称 |
| 全部 | 不填具体名称，作为其他规则未匹配时的兜底 |
| 正则匹配 | 由熟悉表达式的人员提供，普通使用优先选择前两种 |

全部规则作为兜底，不应仅靠把其权重调小来覆盖具体规则。时间控制是否继续使用已有缓存，不代表定时把所有镜像提前下载一遍。

## 七、命名空间前缀什么时候有用

当前页面用 **存储目录** 设置缓存保存前缀。例如保存仓库为 `https://cache-store.example.com`，目录 `/cache`，镜像 `library/nginx:1.28` 保存为 `cache/library/nginx:1.28`。

使用方仍通过缓存入口请求 `library/nginx:1.28`，不要把保存目录 `/cache` 直接加到客户端镜像名称上。

这里的目录是仓库内的镜像路径，不是服务器上的文件夹，也不是面板中的项目分区。

## 八、代理什么时候会影响镜像缓存

代理用于缓存服务无法直接访问镜像源的网络环境。进入镜像源对应行的 **设置 → 访问代理** 填写地址、端口，再确认并保存站点。

代理地址不是原始镜像仓库地址。改动后先下载一个镜像验证；某个来源失败时，同时核对它的网络、账号和代理。

## 九、缓存工作流怎么理解

1. 使用方通过缓存入口请求镜像。
2. 匹配的规则已开启、并且已有可用缓存时，读取保存仓库中的内容。
3. 没有可用缓存时，向配置的来源查找并下载。
4. 符合缓存条件的内容会另行同步到保存仓库。

下载成功和缓存同步完成不是同一件事，前一次请求成功时，后台同步仍可能尚未完成。

### 查看同步状态

在站点列表点击 **查看同步状态**，查看目标仓库、镜像版本、状态、进度、失败信息和更新时间。

- **同步中**：等待并查看进度变化。
- **同步失败**：检查保存仓库写入权限、来源连通性和错误提示，再由管理员处理。
- **没有未完成或失败任务**：当前没有此类任务，不代表所有镜像都已经下载过。

当前页面不是完整的成功历史记录，也没有手动重试按钮。不要靠删除站点来重试同步。

## 十、常见使用链路

### 使用示例：为 Nginx 镜像配置一小时缓存

假设缓存入口为 `mirror.example.com`，管理员已准备保存仓库：

1. 添加该站点，完成域名解析与需要的 HTTPS 设置。
2. 在 **缓存镜像仓库配置** 选择全局配置，存储目录填写 `/cache`，核对仓库账号。
3. 在 **缓存镜像配置 → 源站信息配置** 中选择 `https://`，填写 `registry-1.docker.io`。这一公共源需能从缓存服务访问。
4. 新增缓存规则，打开缓存，时间填 `60`，选择 **精准匹配**，名称填 `library/nginx`，权重填 `1`；分布下载先关闭。
5. 保存后，在已安装 Docker 且能够访问该入口的测试服务器执行：

```sh
docker pull mirror.example.com/library/nginx:1.28
```

6. 如果保存仓库为私有，先按管理员要求完成缓存入口登录。下载后到列表查看同步状态，确认没有失败。
7. 同步完成后结合管理员检查的保存仓库内容，验证镜像已缓存。服务器自身也可能有本地副本，不能只凭第二次下载很快判断缓存服务命中。

示例域名需替换成自己的缓存入口，不是保存仓库地址。

### 让服务器继续使用原来的镜像名称

不想每次手动改成缓存域名时，可使用公开首页的 **镜像配置生成器**：

1. 选择实际使用的配置类型，如 Docker 或 K3s。
2. 勾选需要使用的加速节点。
3. 点击 **复制配置**，按页面给出的保存位置和生效方式，请管理员应用到测试服务器。
4. 保留服务器原有必要设置，不要直接覆盖整份配置；按提示确认是否需要重启相关服务。
5. 再下载原名称的镜像，检查是否经过该入口。

生成器还支持 Podman、不同版本的 Containerd 和 Nerdctl。站点没有填写适用源站时无法生成对应配置，应先补齐源站信息。

## 十一、什么时候优先检查这个应用本身

| 现象 | 检查方法 |
| --- | --- |
| 提示未配置全局仓库 | 先保存全局配置，或为本站点选择自定义仓库 |
| 提示镜像源和源站配置错误 | 至少填写一个可访问的来源，并保存 |
| 提示无权限 | 分别核对源仓库、保存仓库和使用方读取权限 |
| 镜像不存在 | 检查名称、标签和指定来源，匹配栏不填写版本标签 |
| 下载成功但同步失败 | 打开同步状态，核对保存仓库写入权限和失败信息 |
| 下载仍走旧入口 | 服务器可能尚未应用生成配置，或没有按要求重启 |
| 配置生成器没有可选站点 | 确认站点已填写适用源站，入口可用且资料已保存 |

修改规则、代理或保存仓库前先记录原值，一次只调整一类设置并验证。

## 使用建议

- 从一个公开镜像开始测试，确认下载与同步都正常后再扩大缓存范围。
- 规则匹配名称不带版本标签，缓存时间单位为分钟。
- 缓存服务配置和服务器接入分别完成，不能省略其中一步。
- 删除配置前安排使用方切换入口，清理保存仓库由管理员另行处理。

应用源码见 [w7panel-registrycache](https://github.com/w7panel/w7panel-registrycache)。
